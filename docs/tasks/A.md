# A: ファイル入出力の中核（文字コード・改行・安全な保存・外部変更検知）

担当: Fable。データ消失に直結するため最重要。共通指示は `_common.md`。

## 担当パス
`src/text/`、`src/file/`、それらのテスト（`tests/` 配下に置く場合は `tests/file_*.rs`、`tests/text_*.rs`）。

## 要件（`requirements.md` の「通常編集と巨大ファイル」と追加要件 C の保存部分）
1. 文字コード判定: BOM（UTF-8／UTF-16LE／UTF-16BE）、BOM なしは UTF-8 として妥当か → UTF-16 らしさ（NUL の分布）→ CP932（`encoding_rs::SHIFT_JIS`。Windows の CP932 相当として扱う。機種依存文字の扱いを確認し記録）。判定の根拠と信頼度を返す。手動指定で開き直すための API。
2. デコード: バイト列 → UTF-8 文字列（Scintilla は UTF-8 で持つ）。不正なバイトの扱いを決める（置換して警告＋保存時に元へ戻せないことを知らせる、など。黙って壊さない）。
3. 改行形式の判定（CRLF／LF／CR／混在）と保持。保存時は元の改行形式に統一または保持する方針を `architecture.md` と整合させる。
4. エンコード: 元の文字コード・BOM・改行で書き出す。UTF-16 は BOM とバイト順を明示的に処理する。**変換できない文字**を検出し、位置（行・列）と文字の一覧を返す API（上書き前に利用者へ知らせるため）。
5. 安全な保存: 同じディレクトリに一時ファイルを書き、`FlushFileBuffers` 相当で確定させてから置換（Windows では `ReplaceFileW` または `MoveFileExW(MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH)`。属性・ACL の扱いを検討して記録）。失敗時は元ファイルを残し、一時ファイルを片付け、原因を分類したエラーを返す。新規作成・読み取り専用属性・ロック中・ディスク不足・パスが長い場合を考える。Windows 固有部分は `#[cfg(windows)]` で分け、Linux ネイティブでもロジックがテストできるようにする。
6. 外部変更の検知: 開いたときと保存したときのファイルの同一性（サイズ、更新時刻、可能ならファイル ID）を記録し、確認時に変化を判定する API。保存直前にも確認して、外部で変更されていたら上書きせずに知らせる。
7. 100 MiB 級で遅くならない実装（ストリーミング、余計なコピーを避ける）。

## テスト
- `tests/fixtures/` の全パターンで、読み込み → 書き出しがバイト単位で一致する往復テスト。
- 変換不能文字の検出、保存失敗（書き込み不可ディレクトリ等）で元ファイルが無傷であること、外部変更の検知。
- 可能なら乱数による往復の性質テスト（依存は増やさず、簡易な乱数で）。
