# 改善タスク V1〜V3（一般のエディタとの比較による指摘、2026-11-14）

担当: Sonnet（1 つずつ順に実施）。共通指示は `_common.md`。U と同じく、統合作業として `src/ui/` 全体、`src/main.rs`、`src/command/` の既定キー、`src/appdata/settings.rs`、`src/memo/`（V2 のみ）、`Cargo.toml`（`windows` の機能フラグのみ）の編集を許可する。変更した挙動は `docs/spec.md` に反映し、Windows 実機の確認項目を `docs/verification/V.md` に追記する。

**テストは関係するものだけ回す**（例: `cargo test --lib --target x86_64-unknown-linux-gnu <モジュール名>`、変更した UI の自己診断）。全体の品質関門は統括が最後に 1 回行う。ただし `cargo build` と `cargo clippy --all-targets -- -D warnings` は報告前に通す。

## V1: 起動・終了とウィンドウ

1. **無題タブを無条件に作らない。** 文書が 0 件の状態を許す。
   - 起動時: 開くファイルも受け渡し（`--adopt`）も前回のタブの復元もなければ、文書 0 件で起動する。
   - **不具合修正**: タブを切り離して新しいプロセスを起動すると無題タブが余分にできる。原因は `src/ui/app/mod.rs` の `run` で、`adopt_handoff`／`open_path` の読み込みが非同期（`self.opening`）なのに `app.docs.is_empty()` だけで判断して `new_untitled()` していること。
   - 最後のタブを閉じたとき（`close_document`）、「すべて閉じる」の後、開くのに失敗したとき（`ensure_a_document`）も無題を作らず 0 件にする。
   - 0 件のときは編集欄（Scintilla）を隠し、本文の場所に簡単な案内（「Ctrl+N 新規　Ctrl+O 開く」と最近使ったファイル数件。クリックで開ければなおよい。難しければ文字だけ）をテーマの色で描く。タブバーのダブルクリックで新規は従来どおり。
   - 0 件のときに文書を前提とするコマンド（保存、検索、印刷、編集、表示のうち文書に作用するもの、プレビュー等）は実行不可（メニュー無効、ショートカットは何もしない）。`active: Option<usize>` が `None` になる経路をすべて点検し、パニックしないこと。ステータスバーの文書情報は空にする。
2. **前回のタブを復元。** 正常終了時（すべての確認を通って終了するとき）に、ファイルのある通常文書と巨大文書のパス・タブ順・アクティブなタブ・カーソル位置（先頭行の位置も可能なら）を `%LOCALAPPDATA%\Linote\session.json` に原子的に書く（`appdata` の既存の書き込み関数を使う）。起動時に引数・`--adopt` がなければ読み、存在するファイルを開いて順序とカーソルを戻す（存在しないものは黙って飛ばす）。無題・メモ・クリップボード由来は対象外（未保存分は既存の復元データが担う）。複数ウィンドウでは最後に終了したウィンドウの内容が残る（それでよい）。設定 `restore_session`（真偽値、既定 `true`）で無効にできる。起動を重くしないこと（読み込みは既存の非同期の開く処理を使う）。
3. **ウィンドウの位置・大きさ・最大化の記憶。** 終了時に `GetWindowPlacement` を `settings.json` の `window` に保存し、起動時に復元する（`--adopt` で位置指定があるときはそちら優先）。画面外になる場合はモニターの作業領域内に収める。
4. **矩形選択の確認。** Alt＋ドラッグと Alt＋Shift＋矢印は `src/ui/editor/mod.rs` で設定済み。Alt を離したときにメニューバーへフォーカスが移って入力が奪われないか確認し、移るなら Alt＋ドラッグの後の `WM_SYSKEYUP`（VK_MENU）をメニューに渡さないようにする。編集メニューに「矩形選択」（`edit.rectangular_select`、次のマウス選択・矢印選択を矩形にする切り替え。`SCI_SETSELECTIONMODE`）を追加する。

合格条件: 0 件状態・セッションの読み書き（純粋関数・JSON の往復）・ウィンドウ位置の補正の単体テスト、自己診断で 0 件起動・最後のタブを閉じる・タブの受け渡しで無題ができないことを確認。

## V2: タブとメモの小物

1. **すべて保存**（`file.save_all`、Ctrl+Alt+S は既存のグローバルキーと衝突しないか確認して決める）。変更のある文書を左から順に保存。名前のない文書は保存ダイアログを出し、取り消したらそこで止める。メモは保存、巨大は対象外。
2. **閉じたタブを開き直す**（`file.reopen_closed`、Ctrl+Shift+T）。閉じたファイルのパスとカーソル位置を最大 20 件まで覚え（その起動の間だけ）、新しいものから開く。ファイルがなければ飛ばして次へ。メモは ID で開き直す。
3. **メモの削除**: メモ一覧の小窓に「削除」ボタンと Delete キー。確認ダイアログを出し、`MemoStore::delete` を版付きで呼ぶ。開いているタブがあれば閉じる。版の不一致は通知して削除しない。
4. **言語の手動選択**（表示 > 言語、`view.language`、引数 `language`）。対応言語の一覧と「なし（プレーンテキスト）」「拡張子から自動」。文書ごとに保持（保存しない）。ステータスバーの言語名に反映。

## V3: 検索

1. **検索・置換の履歴**: 検索欄・置換欄・Grep の起点欄をドロップダウン付き（`CBS_DROPDOWN`）にし、実行した語を新しい順に最大 20 件、`settings.json` の `search_history`（`find`／`replace`／`grep_dir`）に保存。重複は先頭へ。
2. **選択範囲内の検索**: 「選択範囲内のみ置換」を「選択範囲内」に一般化し、次へ・前へ・全一致の強調・件数も選択範囲に限定する。オンにした時点の選択範囲を Scintilla のインジケーターで示して保持する（編集で範囲がずれても追従するようインジケーターから範囲を読む）。

   - 読めない（壊れている）ときは今の設定を保ったまま状態欄で知らせ、以後の書き込みは既存の規則どおり止める。直って読めたら書き込みを再開する。

## V5: 新規文書の既定と保存時の整形

1. **新規文書の既定**: `settings.json` に `new_file`（`encoding`: `"utf-8"`／`"utf-8-bom"`／`"shift_jis"` など、既存の「保存時の文字コード」で選べるものの名前、既定 `"utf-8"`。`eol`: `"crlf"`／`"lf"`、既定 `"crlf"`）。無題の文書（新規、タブバーのダブルクリック、0 件状態からの新規）に適用する。クリップボード由来の新規タブも同じ。メモは対象外。
2. **保存時の整形**: `settings.json` に `save`（`trim_trailing_whitespace`: 真偽値、既定 `false`。`ensure_final_newline`: 真偽値、既定 `false`）。
   - 上書き保存・名前を付けて保存・すべて保存で、ファイルに書く前に本文を整形する。メモと巨大文書は対象外。
   - 行末の空白の除去は、Markdown の文書（言語が Markdown）では行わない（行末 2 つの空白が改行の意味を持つため）。
   - 最終行の改行は、本文が空なら足さない。足す改行は文書の改行形式に合わせる。
   - 整形は Scintilla 上で 1 回の Undo で戻せる単位として行い、カーソル・選択・先頭表示行をできるだけ保つ。変化がなければ何もしない（未保存の印も版も動かさない）。
   - 整形の計算（どの範囲をどう変えるか）は GUI 非依存の純粋関数にする（既存の「行末の空白を削除」の実装があれば共用する）。
3. 設定画面（V4-1）の「一般」または新しい「ファイル」ページに 1.・2. の項目を足す。

合格条件: 整形の純粋関数の単体テスト（CRLF／LF／CR、空の本文、最終行が空白だけ、Markdown の扱い）、自己診断で新規文書の文字コード・改行と、保存時の整形と Undo。

## V6: 行の整理とブックマーク

1. **行の整理**（編集 > 行の操作▸ に追加）: 「昇順で並べ替え」（`edit.sort_lines_asc`）、「降順で並べ替え」（`edit.sort_lines_desc`）、「重複する行を削除」（`edit.remove_duplicate_lines`、最初の出現を残す）。
   - 対象は選択範囲を含む行全体（選択の終わりが行頭ならその行は含めない）。選択がなければ文書全体。矩形選択・複数選択のときは選択の最初の行から最後の行まで。
   - 並べ替えは安定で、比較は Unicode のコードポイント順（大文字小文字を区別）。数値順や大文字小文字の無視は今回は不要。
   - 最終行の改行の有無は保つ。1 回の Undo で戻せる。変化がなければ何もしない。巨大文書・読み取り専用では無効。
   - 計算は GUI 非依存の純粋関数にする。
2. **ブックマーク**（検索メニューに追加。文書ごと、保存しない）: 「ブックマークの設定/解除」（`search.toggle_bookmark`、`Ctrl+F2`）、「次のブックマーク」（`search.next_bookmark`、`F2`）、「前のブックマーク」（`search.prev_bookmark`、`Shift+F2`）、「すべてのブックマークを解除」（`search.clear_bookmarks`）。
   - Scintilla のマーカーで行番号の余白に印を出す（テーマの色に合わせる）。行番号の表示を消していても印が見えるよう、印用の余白を用意する（幅は小さく）。余白のクリックでも付け外しできるとよい。
   - 次・前は末尾・先頭で折り返し、移った行を画面内に表示する。ブックマークがなければ状態欄で知らせる。
   - 既存のキー割り当て（F2 系）と衝突しないか確かめる。巨大文書では無効。
3. `docs/spec.md` の編集メニュー・検索メニューの並びとコマンド表を更新する。

合格条件: 行の整理の純粋関数の単体テスト（選択範囲の扱い、最終行の改行、空行、重複の判定）、自己診断で並べ替えと Undo、ブックマークの付け外しと移動。

## V7: Grep の絞り込み、外部変更時の動作、最近使ったファイル

1. **Grep の絞り込み**: 検索・置換・Grep の小窓の Grep の部分に「対象」（拡張子。`*.rs;*.txt`、`rs txt` などを受け付ける。空ならすべて）、「除外フォルダー」（`;` 区切り。既定は今の既定の除外）、「隠しファイルも対象」のチェックを足し、中核の `GrepOptions` に渡す。入力の解釈は GUI 非依存の純粋関数にする。値は `settings.json` の `grep`（`extensions`、`exclude_dirs`、`include_hidden`）に保存する（実行時に保存）。「対象」の欄は V3 の履歴と同じくドロップダウン付きにしてよい（任意）。
2. **外部変更時の動作**: `settings.json` に `external_change`（`"notify"`：今の動作、既定／`"reload_if_clean"`：未保存の変更がない文書は自動で読み直す）。
   - 自動の読み直しは同じタブの位置で行い、カーソル位置と先頭表示行をできるだけ保つ（行数が減っていれば収める）。文字コードは開いたときのものを使う（自動判定にしない）。状態欄に「「名前」をディスクから読み直しました」と出す。
   - 未保存の変更がある文書、削除・移動された文書は今の動作（通知して上書き保存を止める）。巨大文書は対象外。
   - 読み直しは非同期の読み込みを使い、結果を反映する前に文書 ID と版を照合する（読み込み中に編集されたら反映せず通知に切り替える）。
3. **最近使ったファイル**: `settings.json` に `recent_files_max`（整数 0〜30、既定 10。0 なら記録しない）。ファイル > 最近使ったファイル▸ の末尾に「｜」「一覧を消去」（`file.clear_recent`、確認なし、一覧が空なら無効）。件数を減らしたら保存時に切り詰める。メニューの番号付けは 10 件を超える場合も崩れないようにする（10 件目以降は番号なしでよい）。0 件状態の案内の最近使ったファイルも同じ一覧を使う。
4. 設定画面（V4-1）に 1.〜3. の項目を足す（Grep の項目は小窓で変えられるので設定画面には不要）。第 17 章の「Grep の絞り込み」の差分の行を改める。

合格条件: 拡張子・除外の入力の解釈、設定の読み書き、最近使ったファイルの件数制限の単体テスト。自己診断で外部変更 → 自動の読み直し（未保存なら通知のまま）、一覧の消去。

# 改善タスク V8: 起動オプション（2026-11-16 追加）

条件は V4〜V7 と同じ（Sonnet で 1 つ、関係するテストのみ、`cargo build`・`cargo clippy --all-targets -- -D warnings`・`cargo fmt` は報告前に通す、`docs/spec.md` と `docs/verification/V.md` を更新）。このタスクに限り、`src/main.rs` と `src/lib.rs`（新しいモジュールの登録）の編集も許可する。`Cargo.toml` の版は統括が上げる。

現状は、コマンドラインのパスをタブで開くだけで、`-` で始まる知らない引数もファイル名として扱い、毎回新しいウィンドウ（プロセス）になる。一般的なエディタの起動オプションに合わせる。

## 1. 引数の解釈（GUI 非依存の純粋関数）

`src/cli.rs` などに置き、Linux ネイティブで単体テストする。結果は「起動要求」の構造体（ファイルの一覧（各ファイルに行・桁・文字コード・読み取り専用）、標準入力を読むか、ウィンドウの選び方、セッション復元の有無、ヘルプ・版の表示、内部用の `--adopt`／`--pos`／`--self-test`）。

| オプション | 意味 |
|---|---|
| `-n <行>`、`-n<行>`、`--line <行>`、`+<行>` | 開くファイルのカーソル行（1 始まり） |
| `-c <桁>`、`-c<桁>`、`--column <桁>` | カーソルの桁（1 始まり、文字単位） |
| `-g <ファイル>:<行>[:<桁>]`、`--goto ...` | そのファイルだけ行・桁を指定（`C:\a.txt:10:5` のようなドライブ文字の `:` を正しく扱う。末尾から数字の部分を切り出す） |
| `-r`、`--readonly` | 読み取り専用で開く（編集不可、上書き保存不可。既存の読み取り専用の扱いがあればそれを使い、なければ Scintilla の読み取り専用と保存の禁止で実装し、ステータスバーに「読み取り専用」） |
| `-e <名前>`、`--encoding <名前>` | 文字コードを指定して開く（名前は V5 の `new_file.encoding` と同じ表記と別名。既存の「文字コードを指定して開き直す」と同じ読み込み） |
| `-` | 標準入力を読み、無題の文書として開く（文字コードは自動判定。読めないときは知らせる） |
| `-w`、`--new-window` | 既存のウィンドウに渡さず、新しいウィンドウで開く |
| `--reuse-window` | 設定にかかわらず既存のウィンドウに渡す |
| `--no-session` | 前回のタブを開き直さない |
| `-h`、`--help`、`/?` | 使い方をダイアログで表示して終了 |
| `-v`、`--version` | 版（`CARGO_PKG_VERSION`）をダイアログで表示して終了 |
| `--` | 以降はすべてファイル名 |

- `-n`／`-c`／`-r`／`-e` は、それより後に書いたファイルすべてに適用する（次の同じオプションで上書き）。`-g` はそのファイルだけ。
- 知らないオプション（`-` で始まる。`--` の後と単独の `-` は除く）は、ファイル名として開かず、「不明なオプション: …」と使い方をダイアログで出して終了する。
- 数値が不正（0、負、数字でない）なら同様にエラー。行・桁が文書より大きければ末尾に収める。
- 相対パスは**起動したプロセスのカレントフォルダー**で絶対パスにしてから扱う（既存のウィンドウに渡すため）。

## 2. 既存のウィンドウで開く（単一ウィンドウ化）

- 設定 `open_in_existing_window`（真偽値、既定 `true`）。設定画面の「一般」ページに追加する（`src/appdata/settings/items.rs` の表）。
- 起動時、`--new-window`・`--adopt`・`--self-test` がなく、設定が真（または `--reuse-window`）なら、既存の Linote のメインウィンドウ（クラス `LinoteMainWindow`。複数あれば Z 順でいちばん手前、つまり最後に使ったもの。自分のプロセスは除く）を探す。
  - 見つかれば、起動要求を `WM_COPYDATA` で渡す（形式は版付きの JSON などで、識別用の `dwData` を決める。標準入力の内容も含める。大きすぎる場合（例: 64 MiB 超）は渡さず自分で開く）。送る前に `AllowSetForegroundWindow` で相手の前面化を許す。`SendMessageTimeoutW`（例: 5 秒、`SMTO_ABORTIFHUNG`）で送り、受け取りの成功が返れば自分は何も表示せず終了する。失敗・時間切れ・応答なしなら、自分で新しいウィンドウを開く（今の動作）。
  - ファイルの引数がなく標準入力もないときは、既存のウィンドウを前面に出す（最小化されていれば元に戻す）だけで終了する。前回のタブの二重復元を防ぐため。
  - 受け取った側: ファイルを今の開く処理（非同期）で開き、既に開いているファイルはそのタブへ切り替える。行・桁・読み取り専用・文字コードを適用し、ウィンドウを前面に出す。0 件状態でも受け取れること。受け取った要求ではセッションの復元をしない。
- 自分から新しいプロセスを起こす箇所（ファイル > 新しいウィンドウ、タブの切り離し `--adopt`、ほかにあれば）は、必ず `--new-window` を付ける（`--adopt` は単独で新しいウィンドウ扱いでもよいが、明示する）。
- 起動を重くしないこと（ウィンドウの探索は `FindWindowExW` の列挙程度）。

## 3. 行・桁へのカーソル移動

- 読み込みが非同期なので、読み込みの完了時（文書 ID を照合）に移動し、その行が画面の中ほどに見えるようにする。既に開いているファイルなら即座に移動。巨大文書は既存の `BigView::goto_line` で行だけ移動（桁は無視でよい）。
- 前回のタブの復元とは同時に起きない（ファイル引数があれば復元しないため）。

## 4. 文書

- `docs/spec.md` の第 1 章（起動）に「起動オプション」の節を作り、表と例（`linote -n 120 a.txt`、`linote -g "C:\src\main.rs:42:7"`、`git diff | linote -`、`linote -w`）、単一ウィンドウの動作、設定 `open_in_existing_window` を書く。第 15 章の設定の表、第 17 章の差分（`--mcp-stdio` の記述は残す）も更新する。
- `docs/verification/V.md` に、関連付けからの連続起動で 1 つのウィンドウにタブが増えること、前面化、別ユーザー・管理者権限のウィンドウ（UIPI で `WM_COPYDATA` が届かない）では新しいウィンドウで開くこと、標準入力のパイプ、などの実機確認項目を書く。

合格条件: 引数の解釈の単体テスト（各オプション、結合形 `-n10`、`+10`、`-g` のドライブ文字、`--`、`-`、不明なオプション、数値エラー、相対パスの解決）、受け渡しの形式の往復テスト。自己診断で、受け取り側の処理（要求を直接渡して、開く・既存タブへの切り替え・行への移動・読み取り専用）と、`WM_COPYDATA` での受け渡し（同じプロセス内で窓を作って送るなど、可能な範囲）。

# 改善タスク V9: Markdown プレビューの対象を広げる（2026-11-16 追加）

条件は V4〜V8 と同じ。編集を許可する範囲: `src/ui/app/preview.rs` を中心に `src/ui/app/`、`src/ui/preview/`、`src/ui/app/commands.rs`（説明文）、自己診断、`docs/spec.md`、`docs/verification/V.md`。`Cargo.toml` の版は統括が上げる。

現状は、拡張子が `.md`／`.markdown` のファイルか、まだファイルでない文書で言語が Markdown のものだけがプレビューの対象（`src/ui/app/preview.rs` の `is_markdown`）。利用者の要望: **保存前の無題の文書や、拡張子が `.md` でないファイルでもプレビューできるようにする。**

1. プレビューの対象を「本文を Scintilla で編集している文書すべて」にする（無題、任意の拡張子のファイル、クリップボード由来、メモ、読み取り専用で開いた文書を含む。巨大文書（`DocView::External`）は対象外のまま）。言語の指定や拡張子は問わず、本文を Markdown として変換する。
2. 開くとき（右ペイン・別ウィンドウ）はアクティブな文書を対象にする。プレビューを開いている間は、アクティブになった文書（対象になるもの）に追従する。巨大文書がアクティブになったときは追従せず、直前の文書の表示を保つ（今の「Markdown でないときは追従しない」と同じ扱い）。
3. 「Markdown の文書（拡張子 .md または .markdown）でだけプレビューできます」の案内は、巨大文書と文書 0 件のときの案内（「巨大ファイルはプレビューできません」など）に置き換える。メニューの有効・無効も同じ条件に合わせる。
4. 16 MiB の上限、WebView2 の遅延初期化、版の照合、右ペインと別ウィンドウの切り替えは今のまま。無題の文書の画像などの相対パスは、基準のフォルダーがないので解決しなくてよい（今の扱いを確認して、おかしな挙動がなければそのまま）。
5. `docs/spec.md` の第 11 章、種類の表（第 2 章の「プレビュー」の列）、コマンドの説明、第 17 章の差分の行（「Markdown のプレビュー対象」）と未確認の項目（メモのプレビュー可否）を更新し、`docs/verification/V.md` に実機確認項目を足す。

合格条件: 自己診断で、無題の文書・`.txt` のファイル・メモでプレビューが開けて内容が反映されること、タブの切り替えで追従し巨大文書では追従しないこと（WebView2 が Wine で使えない場合は、対象の判定と追従の判断の部分を確かめる）。
