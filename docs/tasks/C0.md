# C0: 共通の取り決め（アーキテクチャと中核の型）

担当: Fable。最重要タスク。以後のすべてのワーカーがこの取り決めに従って並行実装する。

## 目的

`docs/requirements.md`（特に「推奨構成と保守性」と追加要件 A〜C）を満たすため、モジュール構成と、モジュール間で共有する型・トレイトを決めてコードとして定義する。中身の実装は各タスクが行うので、ここでは**型・トレイト・関数シグネチャ・ドキュメントコメント・最小限のテスト**までとする（`todo!()` は使わず、未実装部分はモジュールを空にしておくか、明確なエラーを返す）。

## 成果物

1. `docs/architecture.md`（日本語）
   - モジュール構成と依存方向（GUI 非依存の中核 → `ui`／`platform` の一方向）。
   - 各モジュールの責務と、どのタスク（`docs/PLAN.md` の ID）が担当するか、担当パス。
   - スレッドモデル: UI スレッド、バックグラウンド処理（ワーカースレッド／スレッドプール。重い依存を足さない）、結果を UI に戻す方法（`PostMessageW` によるウィンドウメッセージ＋キュー等）、文書ID・版の照合。
   - 版付き文書モデル: `DocumentId`、`Version`（利用者の編集・AI の編集で進む）、文書の種類（通常／巨大読み取り専用／新規未保存／メモ／クリップボード由来）と機能（保存可否、Undo 可否、編集可否）。通常編集の本文は Scintilla が持ち、Rust 側は全文コピーを常時持たない（要件）。版の進め方（Scintilla の `SCN_MODIFIED` 等で進める想定）を記述。
   - コマンド: `CommandId`、機械可読な定義（名前、説明、引数スキーマ、実行可能条件、結果）、実行者（`Actor::User`／`Actor::Ai`）、版の前提条件、Undo 単位のまとめ方。メニュー・ショートカット・将来の MCP が同じ入口を通る設計。
   - 中止・進捗・件数上限の共通の仕組み（`CancelToken`、進捗通知、上限）。
   - エラー型の方針。
   - データ保存場所（`%LOCALAPPDATA%\Linote` 配下のレイアウト: 設定、メモ、復元、MCP 認可・操作記録）と、別プロセス・複数ウィンドウからの同時アクセスの基本方針（ロック、原子的置換、版の照合）。
   - 設定（キー割り当て等）の形式。依存を増やさないため、簡単な独自形式か、`serde`＋`serde_json` 程度にとどめる判断を記録。
   - 遅延初期化の方針（WebView2、MCP、メモ一覧、Grep）。
   - WebView2: GNU ターゲットでは `webview2-com-sys` が `WebView2Loader.dll` に依存するため使わない。COM の型定義（`webview2-com` の `Microsoft::Web::WebView2::Win32` のインターフェース）は使ってよいが、`CreateCoreWebView2EnvironmentWithOptions` 等ローダーの関数は呼ばない。代わりに、インストール済みランタイムをレジストリ（EdgeUpdate の Clients キー `{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`、HKLM／HKCU、WOW6432Node）から探し、`<runtime>\EBWebView\x64\EmbeddedBrowserWebView.dll` を `LoadLibraryW` して `CreateWebViewEnvironmentWithOptionsInternal` を呼ぶ自前ローダーを `platform::webview2_loader` に置く（タスク H）。プレビュー初回まで一切読み込まない。
   - 将来の MCP（要件 C）: 中継口の型（要求・応答・コマンド呼び出し）だけを定義する場所と方針。初版では実装しない。
   - 設計判断の記録（ADR 形式の短い節）。
2. Rust コード（`src/` 配下）
   - `src/lib.rs` にモジュール宣言を追加し、各モジュールの `mod.rs`（または `foo.rs`）に、上記の共有の型・トレイトを定義する。GUI 非依存の中核モジュールは `windows` crate に依存しない。
   - 少なくとも: `core`（ID、版、エラー、`CancelToken`、進捗、上限）、`document`（文書モデルと機能）、`command`（コマンド定義・登録表の型・実行者・前提条件）、`appdata`（保存場所のパス解決。`%LOCALAPPDATA%` は環境変数から取得し、テストで差し替え可能に）、`mcp`（型のみ、初版は空に近くてよい）。
   - 各ワーカー用の空モジュール（`text`、`file`、`memo`、`recovery`、`search`、`bigfile`、`markdown`、`ui`、`platform`）を宣言し、モジュール先頭のドキュメントコメントに責務と、使うべき共通型を書く。
   - 単体テスト（Linux ネイティブでも Windows/Wine でも通ること）。
3. `docs/PLAN.md` の C0 の行を「👀 レビュー中」に更新する。

## 制約

- `Cargo.toml` に依存を足す必要があれば足してよい（このタスクに限り共有ファイルの編集を許可）。ただし軽量性と単体 EXE を優先し、追加理由を `architecture.md` に記す。
- `src/main.rs` の現在のスモークテスト（Scintilla の登録と生成）は残す。
- 既存のビルドを壊さない。

## 合格条件

- `cargo build`、`cargo test`（Wine）、`cargo test --lib --target x86_64-unknown-linux-gnu`、`cargo fmt --check`、`cargo clippy --all-targets -- -D warnings` が通る。
- 後続の各タスク（A, B, D, E, F, G, H, J, K, L）が、`architecture.md` と型定義だけを読んで、他のタスクと衝突せずに並行実装できる。
