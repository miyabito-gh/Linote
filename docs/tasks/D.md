# D: 未保存変更の復元データ

担当: Fable。強制終了・複数ウィンドウ・別プロセスでの整合性が要。共通指示は `_common.md`。

## 担当パス
`src/recovery/` とそのテスト。

## 要件（`requirements.md` の「一時メモと未保存変更の復元」、追加要件 C）
1. 通常ファイル、未保存の新規タブ、クリップボード由来のタブ、（将来）AI が変更した文書を、復元データとして `%LOCALAPPDATA%\Linote\recovery\`（`appdata` モジュールで解決）に書き出す。入力が落ち着いた時点・一定間隔（間隔は設定可能、既定値を提案）で書く。書き出しは UI スレッド外。
2. 形式: 本文（UTF-8）と付随情報（元ファイルのパス、文字コード・BOM・改行、元ファイルの同一性情報、版、タイトル、作成・更新時刻、所有プロセス）。形式に版番号を付ける。原子的に書く（一時ファイル→置換）。壊れた・未知の版のデータは削除せず隔離して報告する。
3. 所有と排他: 各ウィンドウ（プロセス）が自分の復元データを持ち、他のプロセスのデータを上書きしない。生存中のプロセスのデータと、強制終了で残ったデータ（孤児）を区別する（ロックファイルを保持し続ける方式など。Windows でのロックの振る舞いを考慮）。同じ文書を複数ウィンドウで開いた場合も互いに上書きしない。
4. 起動時に孤児の復元データを列挙し、復元の候補として返す API。復元しても元ファイルには反映しない（反映は利用者の保存時）。復元時に元ファイルの外部変更を検知できるよう、同一性情報を返す。
5. 保存成功時・利用者が明示的に破棄したときに、対応する復元データを削除する API。
6. 別プロセスが同時に列挙・取得しても壊れないこと（将来の MCP プロセス）。

## テスト
強制終了の模擬（書き込み途中のファイルが残った状態）、2 プロセス相当の同時書き込み、孤児の判定、壊れたデータの隔離、保存・破棄時の削除。Linux ネイティブでもロジックをテストできるようにする（Windows 固有のロックは `cfg` で分け、Wine でもテスト）。
