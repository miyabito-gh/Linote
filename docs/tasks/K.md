# K: 文書内検索・置換と Grep

担当: Opus。共通指示は `_common.md`。

## 担当パス
`src/search/`（GUI 非依存）、`src/ui/search_panel.rs`（検索バー）、`src/ui/grep_panel.rs`（Grep 結果）。

## 要件（`requirements.md` の「検索・置換・Grep」）
1. 文字列検索と正規表現（Rust `regex`。後方参照・先読み後読みは対象外）。無効なパターンは検索欄にエラー表示。大文字小文字、単語単位。
2. 通常文書の検索・置換は Scintilla 上で行う（`SCI_SEARCHINTARGET` は使わず、本文を範囲ごとに取得して Rust の `regex` で検索し、ヒット位置で選択・置換する方式。巨大な文書ではチャンク処理）。置換は Undo の 1 単位。
3. Grep: フォルダーを指定し、`grep-searcher`（＋`grep-regex`）または自前の行単位検索で、文字コード（UTF-8／UTF-16／CP932 の判定は `text` モジュールの判定を使う）を考慮。除外（バイナリ、大きすぎるファイル、隠しフォルダー、`.git` など）と件数上限。バックグラウンドで実行し、結果を逐次 UI へ。中止可能。
4. 結果は構造化（ファイル、行番号、列、該当行の抜粋、ヒット範囲）。将来 MCP からそのまま返せる形（`architecture.md`）。
5. Grep 結果パネル: 一覧表示、選択でファイルを開いて該当行へジャンプ。
6. 巨大モードの検索は J の API を UI から呼ぶ（検索バーを共通化し、巨大モードでは置換を無効にし、制約を案内）。

## テスト
検索・置換・Grep の単体テスト（文字コード混在フォルダー、中止、件数上限、無効なパターン）。Linux ネイティブでも。
