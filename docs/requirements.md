# Linote 初版要件（Rust製 Windows向け軽量テキストエディタ）

> この文書は利用者から受け取った初版要件を正本として保存したものです。末尾の「追加要件」は、その後の打ち合わせで利用者と合意した内容です。

## 目的と対象

サクラエディタを参考に、日本語のテキスト編集、検索、ログ閲覧を素早く始められるWindowsデスクトップアプリを作る。一時メモとMarkdownプレビューを備え、起動時間とメモリ消費を抑える。機能追加や部品の差し替えをしやすい構成にする。

- 対象は Windows 11 x64。ZIPを展開して起動できる形で配布する。
- 性能目標は **100 MiB級のファイルの編集・保存**と **1 GiB級のファイルの閲覧・検索**。容量は検証目標であり、モード切り替えの固定しきい値は実測で決める。

## 機能要件

### 通常編集と巨大ファイル

- タブで複数文書を開ける。新規作成、開く、保存、名前を付けて保存、Undo／Redo、コピー・貼り付け、日本語IME、行番号、行ジャンプ、矩形選択を用意する。
- 通常編集はUTF-8、UTF-16、CP932相当に対応する。文字コードを表示し、手動指定で開き直せるようにする。保存時は元の文字コード、BOM、改行形式を保持する。変換できない文字があれば上書き前に知らせる。
- 保存では同じディレクトリに一時ファイルを書き出してから置換する。書き込みや置換の失敗を表示し、元ファイルと編集中の内容を保護する。
- 巨大ファイルは読み取り専用モードを用意する。初版の巨大モードはUTF-8を対象とし、先頭表示、スクロール、末尾移動、行ジャンプ、範囲コピー、検索を提供する。折り返しと構文着色は既定でオフにする。読み取り専用であることを画面で示す。
- 編集中または復元時に元ファイルの外部変更を検知したら通知し、編集中の内容を別名で保存できるようにする。巨大モードでも切り詰め・置換で古くなった索引や検索結果を無効化する。

### 検索・置換・Grep

- 文書内の検索・置換と、フォルダーをまたぐGrepに、文字列検索と正規表現検索を用意する。巨大モードは検索を提供する。
- 正規表現には共通のRust `regex` 構文を使う。検索パターンの後方参照、先読み・後読みは対象外。無効なパターンは検索欄にエラーを表示する。
- Grepは対象フォルダーを指定して検索し、結果にファイル名・行番号・該当箇所を表示する。結果を選ぶと該当ファイル・行へ移動する。通常編集で扱う文字コードをGrepでも扱えるようにする。
- 大容量ファイルの検索やGrepは操作を妨げず、中止できるようにする。巨大モードの正規表現検索は行単位を初版の既定とし、検索範囲や制約を画面で案内する。

### 一時メモと未保存変更の復元

- 一時メモは複数作成できる。エディタ内のショートカットで一覧を開き、名前・本文で検索し、選択したメモをすぐ開けるようにする。
- メモはユーザーごとのローカル領域にUTF-8で自動保存する。入力が落ち着いた時点と正常終了時に保存し、一覧は初めて開くときに読み込む。
- 通常ファイルと未保存の新規タブも復元対象とする。強制終了後に、最後に書き出した復元データから編集を再開できるようにする。復元した内容を元ファイルに反映するのは、ユーザーが保存したときとする。
- 元ファイルへの保存が成功したとき、またはユーザーが変更を明示的に破棄したときに、対応する復元データを削除する。同じ文書やメモを複数ウィンドウから扱っても、復元データや本文が互いに上書きされない設計にする。

### グローバルショートカットでクリップボードを展開

- エディタ起動中は、他アプリにフォーカスがある場合も、登録したグローバルショートカットでエディタを前面に表示し、クリップボードのテキストを未保存の新規タブに取り込む。エディタ内でも同じキーで動作する。
- 日本語・タブ・改行を保持する。テキストがない場合は短い状態表示を出す。作成したタブは編集、検索、保存、未保存変更の復元に対応する。
- キー割り当ては設定で変更できる。登録が競合した場合は状態を伝え、再設定できるようにする。クリップボード展開専用のアプリ内キーは設けない。通常の `Ctrl+V` は編集中の文書への貼り付けに使う。

### Markdownプレビュー

- **右ペインと別ウィンドウ**の両方でプレビューを開ける。どちらも編集中の内容を反映し、表、チェックリスト、コードブロックを表示する。変換処理とスタイルは共有する。
- **WebView2はプレビューを初めて開く操作で遅延初期化する。** 通常起動では、ランタイムの有無の確認、ローダーの読み込み、WebView2の環境生成、関連プロセスの起動を行わない。ランタイムが利用できない場合はプレビューを開いた時点で案内し、通常編集は続けられるようにする。
- 変換は入力が落ち着いてからバックグラウンドで行う。文書の編集や閉鎖で古くなった結果は破棄する。埋め込みHTML、スクリプト、外部リソースの自動読み込みは初期状態で無効にする。

## 画面デザイン

- 本文を広く取ったWindows向けの外観。上部に細いファイルタブ、中央に本文、下部に行・列、文字コード、改行形式を表示する。選択中のタブと現在行を控えめに強調し、未保存状態を小さな丸で示す。
- ダークとライトの両テーマを用意し、Windowsの設定に連動させる。ダークの配色初案は本文背景 `#191D24`、上部バー `#212731`、本文 `#E3E8EF`、アクセント `#91ABD0`。色は選択とフォーカスを見分けやすいよう調整する。
- 一時メモは検索できる小窓で表示し、閉じると本文にフォーカスを戻す。Markdownは見出し・段落・コードに余白を取り、本文のテーマと調和させる。
- 画面の参考は、[Zed](https://zed.dev/) のタブや境界、[iA Writer](https://ia.net/writer) の文字と余白、[VS Code](https://code.visualstudio.com/docs/languages/markdown#_markdown-preview) の左右分割、[サクラエディタ](https://sakura-editor.github.io/intro.html) の操作配置。

## 推奨構成と保守性

| 領域 | 初版の構成 |
| --- | --- |
| ウィンドウと画面 | Rustの `windows` crate とWin32。タブとステータスバーを独自描画し、共通のテーマ設定を編集欄とプレビューにも反映する。 |
| 通常編集 | Scintilla。Rustからの呼び出しを画面部品の境界に集め、通常編集の本文はScintillaに持たせる。Rust側に常時全文コピーを保持しない。 |
| 巨大ファイル | バッファ付き部分読み込みと疎な行索引。先頭を先に表示し、残りの索引は裏で作る。表示範囲の描画にはDirectWriteを使う。索引・描画・キャッシュは長大な単一行でもメモリ使用量が膨らまないよう境界を設ける。 |
| 変換・検索 | 文字コード変換は `encoding_rs` を候補とする。UTF-16の書き出しはBOMとバイト順を明示的に処理する。正規表現は `regex`、行単位のGrepは `grep-searcher` を候補とする。 |
| Markdown | `pulldown-cmark` で解析し、HTML/CSSをWebView2で表示する。右ペインと別ウィンドウで解析・描画設定を共有する。 |

- 一つのRustアプリを、画面・テーマ、コマンド、文書・ファイル、検索、メモ、復元、プレビューの役割で分ける。プラグイン機構や複数クレート化は、具体的な必要性が出た段階で判断する。
- メニューとショートカットは同じコマンドを呼ぶ。行ジャンプやコピーなど通常編集と巨大閲覧で共通する操作を揃え、保存やUndoの可否は文書の機能に応じて判断する。
- 長時間のI/O・検索・変換はUIスレッドから外す。結果を反映する前に文書IDと版を照合し、既に閉じた文書や古い版への反映を防ぐ。保存・復元・文字コードの処理は画面を立ち上げずに検証できるようにする。

## 実装順序と受け入れ確認

1. **通常編集と保存。** 空起動、タブ、日本語IME、矩形選択、行ジャンプ、文字コード・改行の保持を確認する。100 MiB級で先頭表示、中央付近の編集、Undo、保存を計測する。保存失敗や外部変更時に元データを守れることを確認する。
2. **メモ・復元・クリップボード。** メモの保存と呼び出し、通常文書とクリップボード由来のタブの強制終了後の復元、保存・破棄後の復元データ削除を確認する。別アプリにフォーカスがある状態からの取り込み、キー競合、テキストがない場合も試す。
3. **Markdown。** 右ペイン・別ウィンドウで編集反映と各表示要素を確認する。WebView2がない環境でも通常編集が使えること、通常起動時にWebView2を読み込まないことを確認する。プレビュー初回の表示時間と追加メモリは本体とWebView2関連プロセスを含めて測る。
4. **巨大ファイルとGrep。** 1 GiB級で先頭表示、末尾移動、行ジャンプ、検索の初回ヒット、検索中止を確認する。短い行が大量にあるファイルと、改行がほぼない長大行を使う。Grepの文字コード、正規表現、結果からのジャンプも確認する。
5. **配布と性能比較。** ZIPを別のWindows 11 x64環境で展開して起動する。同じPC・同じ入力でサクラエディタと比較し、コールド／ウォーム別の起動から入力可能までの時間、待機時と作業中のメモリ、保存・検索の所要時間を記録する。メモリはプライベートバイトとワーキングセットを記録する。IME、キーボード操作、DPI変更、明暗切り替えもWindows上で確認する。

## 初版の対象外と実測で決める項目

- **対象外** — 1 GiB級の編集・保存、ログ追尾、サクラエディタのキー割り当てプリセット、Markdownのローカル画像表示と左右スクロール同期、Windows 10・ARM64、インストーラーと拡張子関連付け。
- **実装時に決める** — グローバルキーとメモ呼び出しキーの初期値、復元の書き出し間隔、巨大モードへの切り替え条件、検索・索引・キャッシュの上限、起動時間やメモリの数値予算。ファイル容量に加え、行数と最大行長で挙動を確かめて決める。

# 追加要件（2026-11-13 合意）

## A. 単体EXEでの配布

- 成果物のEXEは単独で動作する。DLL、ランタイムのインストール、設定ファイルの同梱を必要としない。
- C/C++ランタイム、Scintilla、Lexillaは静的リンクする（GNUターゲットでは `libstdc++`／`libgcc`／`winpthread` を静的リンク、MSVCでは `crt-static`）。
- 設定・メモ・復元データは初めて必要になった時点で `%LOCALAPPDATA%\Linote` に作成する。
- 配布ZIPの中身はEXEと第三者ライセンス表示のみとする。
- WebView2ランタイム本体はWindows 11の標準部品として前提にする。ローダー（`WebView2Loader.dll` 相当）はEXEに組み込むか、Rust実装のローダーを使い、別DLLを配布しない（事前検証で方式を確定する）。
- ビルド時にEXEの読み込むDLLを検査し、Windows標準以外のDLLがあれば失敗とする。

## B. Scintilla と Lexilla

- Scintilla のソースをリポジトリに同梱する（`third_party/scintilla/`）。版・取得元・SHA-256・削除したディレクトリ・ローカル修正を `VENDORED.md` に記録し、ライセンス文を保持して配布ZIPにも含める。Windows以外のプラットフォーム層、テスト、文書は除く。
- 構文着色に Lexilla を同梱し（`third_party/lexilla/`）、**必要な言語の字句解析器だけ**を組み込む。初版の対象言語:
  Markdown、Rust、JSON、TOML、YAML、INI、XML/HTML、C/C++、Java、Python、PowerShell、バッチファイル、SQL、ログ。
  - Java は Lexilla の C++ 系字句解析器を Java のキーワードで使う想定。ログは Lexilla に汎用の字句解析器がないため、方式（簡易な独自着色など）を実装時に決める。
- 巨大モードでは構文着色を既定でオフにする（既存要件どおり）。

## C. ローカルMCP連携（AIとの相互操作）— 初版は構成のみ

### 目的

AIクライアントが Linote のデータ（一時メモ、開いている文書・タブ、選択範囲、ファイル、検索結果）を**読み書き**し、利用者とAIがアプリ内のデータを相互に操作できるようにする。

### 方針

- **ローカル接続のみ**。ネットワークへは公開しない。利用者は1人で、同時接続は1つに限る（2つ目は拒否）。複数人の同時編集は考慮しない。
- ただし**利用者のGUI操作とAIの操作が重なる場合**は扱う。すべての書き込みに前提となる版（文書ID＋版、メモID＋版）を必須にし、食い違えば拒否して最新の版を返す。黙って上書きしない。
- AIによる文書の編集はUndoの1単位とし、利用者が1回で取り消せる。AIの変更は画面で分かるようにし（タブ・ステータス表示、変更箇所の強調）、操作の記録をローカルに残す。
- ファイルへの保存は通常の保存と同じ経路（一時ファイル経由の置換、文字コード・BOM・改行の保持、変換不能文字の確認）を通す。巨大モード（読み取り専用）や外部変更を検知した文書への書き込みは拒否する。AIの変更も未保存変更の復元対象にする。

### 接続方式

- DocTrail（`miyabito-gh/DocTrail` の `app/src/mcp_stdio.rs`、`mcp_authorization.rs`）と同じく、同じEXEを `--mcp-stdio` で起動し、GUIを初期化せずに MCP stdio（JSON-RPC 2.0、改行区切り）で応答する。stdoutは応答専用、診断はstderr。入力サイズと受付待ちに上限を設ける。
- GUIが起動中の場合、MCPプロセスは現在ユーザー専用の名前付きパイプでGUIへ中継し、データの変更はGUIが唯一の窓口として、利用者の操作と同じコマンドで実行する。
- GUIが起動していない場合は、メモの読み書きとファイルの読み取りだけをMCPプロセスが直接行う（ロックと原子的置換、GUIと同じ保存処理）。開いている文書への操作は「GUI未起動」として拒否する。

### 軽量性（遅延）

- MCP連携は既定OFF。OFFのときは名前付きパイプの作成、スレッドの起動、認可ファイルの読み込みを一切行わず、起動時間と常駐メモリに影響を与えない。
- 設定でONにした時点（または起動時にONが保存されていればその時点）で初めて受け付けを始める。待機はCPUを使わない方式（重複I/O等）とし、待機用スレッドは1つまで。
- MCPの処理（JSON解析、操作定義、認可）は通常のGUI起動経路から呼ばない。`--mcp-stdio` 起動時もGUIを初期化せず、必要な中核処理だけを使う。

### 認可

- 既定OFF。DocTrailの方式に倣い、ユーザー単位の認可、期限付き1回限りの許可、明示的な起動時許可を使う。不正・不一致は拒否する。
- 許可範囲は「読み取り」と「書き込み」の2段階。ディスクへの保存と削除は操作ごとにGUIで確認する。対象フォルダーは明示的に許可した範囲に限る。

### 操作の候補

- 読み取り: メモの一覧・検索・本文、開いている文書の一覧・本文（範囲指定）・選択範囲・カーソル位置・文字コード・改行形式、ファイル読み取り、Grep、巨大ファイルの範囲読み取りと検索。
- 書き込み: メモの作成・更新・名前変更・削除、文書への挿入・置換・範囲書き換え、新規タブ作成、ファイルを開く・保存、文書内の検索と置換。

### 段階

- **初版はMCP本体を実装しない**。ただし次を初版の設計で備える:
  - 全操作を版の照合付きコマンドに一本化し、メニュー・ショートカット・将来のAI操作が同じ入口を通る。コマンドの実行者（利用者／AI）を記録できる。
  - 中核処理（文字コード、保存、メモ、復元、検索、巨大ファイル索引）を画面から切り離し、GUIとMCPの両方から呼べる。
  - コマンド定義（名前、引数、実行可能条件、結果）を機械可読にする。
  - メモと復元データは別プロセスからの同時アクセスでも壊れない（ロック、原子的置換、版の照合）。
  - 長時間処理は中止・進捗・件数上限を共通の仕組みで扱う。
- 次の版で、読み取り → メモ書き込み → 文書編集の順に公開する。保存・ファイル操作は操作ごとの確認が整ってから公開する。
