Wine＋Xvfb の自己診断（`integration_v4` の `keys_page`）で通る範囲は済んでいる: 設定画面の「キー」ページ（実際のダイアログ）で、一覧にコマンドが並ぶこと（分類、グローバルショートカットの表示）、絞り込み（キー・語・該当なし）、割り当て、重複して「やめる」と「付け替える」、文字のキーを断ること、外す・既定に戻す・すべて既定に戻す、キー入力欄への押下（F5）、OK で保存され `keys` には既定と違うものだけが残ること、アクセラレーターとメニューのキー表示への反映、開き直した一覧での「変更済」の表示。キーの割り当ての規則（重複の検出と付け替え、既定と同じなら書かない、正規化、変えたコマンドだけの差し替え）は `cargo test --lib` の単体テスト。ここは**実機でしか確かめられない**項目。

- [ ] 設定... の左の一覧に「キー」が加わり、選ぶと コマンドの一覧（分類・コマンド・キー・既定との違い）と、絞り込みの欄、「新しいキー」の欄、ボタン 4 つが出る。一覧の列の見出しと幅が切れず、高 DPI（150%・200%）でも部品が重ならない。画面が小さい（1366×768）でも、ボタンと OK・キャンセル・適用が見える。
- [ ] 絞り込みの欄に「保存」「ctrl+s」「file」などを入れると、一覧が即座に絞られる。消すと全部に戻る。絞り込み中に選んだ行は、絞り込みを変えても（残っていれば）選ばれたまま。
- [ ] 一覧でコマンドを選び、「新しいキー」の欄をクリックして実際にキーを押すと、押した組み合わせが表記で入る（Ctrl+Alt+K、Shift+F3、F キー、矢印、Delete、Ctrl+Shift+Tab、Ctrl+Plus など）。押しながら修飾キーだけ（Ctrl 単独）では何も入らない。Alt を押してもメニューやダイアログの動作（ビープ音、メニューバーへの移動）が起きない。Enter・Esc を押しても、ダイアログが閉じず、キーとして入る（Esc、Enter 単独は文字入力扱いで割り当ては断られる）。Tab・Shift+Tab では次・前の部品へ移る。
- [ ] 「割り当て」で、一覧の「キー」列と「既定との違い」（変更済（既定: …））が替わり、欄が空になる。選ばずに押す、欄が空のまま押すと、案内が出る。一覧の行をダブルクリックすると「新しいキー」の欄へフォーカスが移る。
- [ ] すでに別のコマンドが使っているキーを割り当てると、相手の名前を出して付け替えを確認する。「いいえ」なら何も変わらない。「はい」なら相手の「キー」列が空になり「変更済」と出る。
- [ ] 文字入力を奪うキー（A、Shift+A、5、Space、Enter、Comma など）は「文字の入力に使うため割り当てられません」と断られる。F5、Delete、Shift+Left、Ctrl+A などは割り当てられる。
- [ ] 「割り当てを外す」でキー列が空になる。「既定に戻す」で既定のキーに戻り、「既定との違い」が空になる（戻した先を別のコマンドが使っているときは知らせる）。「すべて既定に戻す」は確認のあと、すべての「変更済」が消える。
- [ ] OK（適用）で、メニューのキー表示（項目の右側）が替わり、新しいキーで実行でき、古い既定のキーは働かなくなる。`settings.json` の `keys` には既定と違うものだけが書かれ、既定に戻したものは消えている。キャンセルでは何も変わらない。画面を開いている間に、ほかのウィンドウで別のコマンドのキーを変えても（その後 OK）、そちらの割り当ては失われない。
- [ ] グローバルショートカット（クリップボードから新しいタブ。一覧に「（グローバル）」付き）: 別のキー（例: Ctrl+Alt+B）に変えて OK すると、他のアプリにフォーカスがあるときも新しいキーで Linote が前面に来てクリップボードの新しいタブができ、古いキー（Ctrl+Alt+V）は解除される。他のアプリが使っているキーにすると、適用のあとに「他のアプリが使用中のため登録できません」の通知が出る。修飾キーなし（F5 など）は断られる。外す（空）と登録が解除される。
- [ ] `settings.json` が壊れているときに「キー」を変えて OK しても、画面の上部の警告どおり、その起動の間だけ反映してファイルは書き換わらない。
- [ ] Win キーを使う組み合わせ（Win+…）の多くは OS が先に処理するため入力欄で受け取れない（`settings.json` を手で書けば登録できる）。IME がオンでも、入力欄にキーの組み合わせが入る（変換モードに入らない）。

## V5 新規文書の既定と保存時の整形

Wine＋Xvfb の自己診断（`integration_v5`）で通る範囲は済んでいる: 無題とクリップボード由来の新しいタブが設定の文字コード・改行（Shift_JIS＋LF、UTF-8 BOM＋CRLF）で作られること、保存時の整形（行末の空白の除去、CRLF／LF の最終行の改行、空の本文は足さない、Markdown では除かない、名前を付けて保存でも行う、1 回の Undo で戻る、カーソルの保持、変化がなければ版を動かさない）、設定画面の「ファイル」ページの項目。整形の計算は `cargo test --lib` の単体テスト（CRLF／LF／CR、空の本文、最終行が空白だけ）。ここは**実機でしか確かめられない**項目。

- [ ] 設定... に「ファイル」ページがあり、新規文書の文字コード・改行の選択と、保存時の 2 つのチェックが見える。高 DPI でも切れない。
- [ ] 新規文書の文字コードを Shift_JIS、改行を LF にして OK し、Ctrl+N で作った無題のステータスバーが「Shift_JIS (CP932)」「LF」になる。日本語を入れて保存し、メモ帳などで開いて文字化けしない。UTF-8 (BOM 付き) にすると BOM 付きで保存される（エクスプローラーのプレビューやほかのエディターで確認）。クリップボードから新しいタブ（Ctrl+Alt+V）も同じ文字コードになる。メモは UTF-8 のまま。
- [ ] 「保存時に行末の空白を削除」をオンにして、行末に空白・タブがあるファイルを Ctrl+S すると、保存後の本文から除かれ、直後の Ctrl+Z で空白が戻る（1 回で全部戻る）。カーソルと表示位置（スクロール）が保存の前後で動かない。全角空白は残る。
- [ ] 同じ設定で `.md` のファイル（または表示 > 言語で Markdown にした文書）の行末の空白は除かれない。
- [ ] 「保存時に最終行の改行を補う」をオンにして、最終行に改行のない文書を保存すると、改行が付く（CRLF の文書には CRLF、LF の文書には LF）。空の文書には付かない。最終行が空白だけの文書の扱い（行末の空白の削除もオンなら空行になる）。カーソルを文書の末尾に置いて保存しても、カーソルは元の文字の後ろに残る。
- [ ] 変化のない文書を保存しても、タブの未保存の印が一瞬も付かない。「名前を付けて保存」「すべて保存」でも整形される。メモと巨大ファイルは整形されない。
- [ ] Ctrl+S の保存に失敗した（読み取り専用ファイルなど）場合や、保存ダイアログを取り消した場合の本文の状態が自然である（取り消しでは整形されない。失敗では整形が残るが Ctrl+Z で戻る）。
