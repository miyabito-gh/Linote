# I2 統合（K・L・H）の Windows 実機確認

対象: 検索・置換・Grep、巨大ファイルのビュー、Markdown プレビュー。
Wine＋Xvfb の自己診断（`linote.exe --self-test`、`ui::app::selftest::integration_i2`）で通る範囲は済んでいる:
検索の次／前と折り返し、置換と「すべて置換」の Undo 1 回（ワーカー経路を含む）、古い結果の破棄、Grep の結果を開いて
行・桁へ移る、小さな閾値での巨大モード（読み取り専用、索引、行への移動、検索、置換・保存の拒否、タブ切り替え）、
プレビューのコマンド（ランタイムなしの案内）。ここは**実機でしか確かめられない**項目。

追加したコマンドとキー:

| コマンド | キー |
|---|---|
| `search.find`（検索...） | Ctrl+F |
| `search.replace`（置換...） | Ctrl+H |
| `search.find_next`／`search.find_prev` | F3／Shift+F3 |
| `search.grep`（フォルダー内を検索） | Ctrl+Shift+F |
| `view.preview_pane`（右ペイン） | Ctrl+Shift+P |
| `view.preview_window`（別ウィンドウ） | なし（メニューのみ） |

巨大モードの既定の閾値: 256 MiB 超、1000 万行超、8 MiB 超の行を含む（`LargeModeThresholds::DEFAULT`。実測のうえ調整する）。

## 1. 起動

- [ ] 起動が速い。タスクマネージャーで `msedgewebview2.exe` が出ない（プレビューを開くまで WebView2 を初期化しない）。
- [ ] 検索の小窓・メモ一覧・Grep は、それぞれ初めて使うまで作られない（起動直後の作業セットが増えない）。

## 2. 検索・置換（通常の文書）

- [ ] Ctrl+F で小窓が開き、検索欄にフォーカスが入る。本文で 1 行の短い文字列を選んでから開くと、検索欄に入る（複数行の選択は入らない）。
- [ ] Enter／次へ、Shift+Enter／前へで本文の一致が選択され、画面内にスクロールする。端で折り返し、折り返したことが状態欄に出る。
- [ ] 小窓を閉じたあと、F3／Shift+F3 で同じ条件の次／前へ移る。検索条件がまだなければ小窓が開く。
- [ ] 大文字小文字の区別、単語単位、正規表現（`(\d+)-(\d+)` を `$2-$1` に置換）が効く。不正な正規表現（`(`）は小窓に理由が出て、本文は変わらない。
- [ ] 全角・サロゲートペア（絵文字）・CRLF を含む文書で、選択範囲が一致の文字とずれない。
- [ ] 置換（1 件）: 選択が一致なら置換して次の一致へ移る。一致でなければ移るだけ。
- [ ] すべて置換: 件数が状態欄に出る。直後の Ctrl+Z 1 回で全部元に戻る。Ctrl+Y でやり直せる。
- [ ] 数十 MiB の文書で検索・すべて置換しても UI が固まらない（4 MiB 以上はワーカーで処理）。置換の最中に編集すると「変更されたため置換していません」と出て、何も置換されない。
- [ ] 読み取り専用の文書（メモを除く）では置換の欄が無効になる。
- [ ] 小窓を開いたまま本文を編集・タブを切り替えられる。小窓を閉じると本文にフォーカスが戻る。暗いテーマ・高 DPI で小窓の配色と大きさが合う。

## 3. Grep

- [ ] Ctrl+Shift+F で小窓が開き、起点のフォルダーに、アクティブな文書のフォルダーが入る。フォルダー欄で Enter すると検索が始まり、結果が一覧に逐次増える。
- [ ] 検索中に中止できる。UI が固まらない。隠しフォルダー・`.git`・`node_modules`・`target`・バイナリ・16 MiB 超のファイルが除外され、件数が状態欄に出る。
- [ ] CP932・UTF-16 のファイルの中の日本語も検索できる。
- [ ] 結果をダブルクリック／Enter すると、そのファイルが開き（開いていればそのタブへ切り替わり）、該当の行・桁にカーソルが移る。全角を含む行でも桁がずれない。
- [ ] 結果が数万件でも一覧が固まらない（上限で打ち切ったことが出る）。

## 4. 巨大ファイル

- [ ] 256 MiB 超のファイル（`scripts/gen-large-fixtures.py` で生成）を開くと、読み取り専用のタブで開く。開くのが一瞬で、メモリが増えない。1 GiB でも同様。
- [ ] ステータスバーに「読み取り専用」、位置（行 N／バイト位置）、索引の進み（「索引作成中 N%」→「索引済み」）が出る。タブにも読み取り専用の印が付く。
- [ ] 索引の作成中もスクロール・移動できる。スクロールバーの操作でファイルの途中へ飛べる。
- [ ] Ctrl+G: 索引が済んだ範囲なら移動できる。未済の行は「作成が済み次第移動します」と出て、済んだら移る。範囲外は最終行へ移り、案内が出る。
- [ ] Ctrl+F: 小窓の置換欄が無効になり、案内（正規表現は行単位）が出る。次／前で一致が表示され、見つからなければ「見つかりません」。検索中も UI が固まらず、別の検索で前の検索が止まる。
- [ ] Ctrl+A／Ctrl+C: 選択して貼り付けた内容が合う。上限（64 MiB）を超える選択は案内が出て、コピーされない。
- [ ] 編集・貼り付け・切り取りは使えない（メニューが灰色）。Ctrl+S は「保存できません」と出て、ファイルは変わらない。
- [ ] 8 MiB 超の 1 行を含む小さなファイル、1000 万行超のファイルも、読み取り専用のビューで開く（UTF-8 のとき）。UTF-8 以外の巨大ファイルは案内が出て開かない。
- [ ] タブを切り替えて戻っても、表示位置・選択が保たれる。ほかのタブを開いたまま閉じても、タイマーが残らない（CPU 使用率が 0 に戻る）。
- [ ] 開いている間に別プログラムで追記・切り詰め・置換すると、「変更されました。閉じて開き直してください」と出る（表示が壊れない）。
- [ ] Direct2D 経路での描画、全角の桁ずれ、数 GB での操作感、高 DPI を確かめる。

## 5. Markdown プレビュー

- [ ] `.md`／`.markdown` のタブで Ctrl+Shift+P: 右ペインにプレビューが出る（編集欄が左、プレビューが右、50:50）。もう一度押すと閉じる。初めて開くときだけ WebView2 の初期化で少し待つ。
- [ ] `.md` でない文書では「Markdown の文書でだけプレビューできます」と出て、何も開かない。
- [ ] 編集すると、入力が止まってから（約 250 ミリ秒、大きい文書ほど長く）プレビューが更新される。更新中も入力が固まらない。連続入力で古い版の結果が表示を上書きしない。
- [ ] 別の Markdown のタブへ切り替えると、プレビューがそのタブに追従する。Markdown でないタブへ切り替えても、プレビューは最後の Markdown 文書のまま（閉じた文書には追従しない）。
- [ ] 表示 > Markdown プレビュー（別ウィンドウ）: 別ウィンドウに出る。閉じるボタンで閉じる。右ペインと同時に開ける。
- [ ] テーマ（ライト／ダーク）を切り替えると、プレビューの背景・文字色が追従する。
- [ ] `<script>`、`onerror=`、外部画像 URL、`javascript:` のリンクが実行・読み込みされない（R3 の観点）。`http(s)` のリンクは既定のブラウザーで開く。
- [ ] 右クリックのメニュー・F12 が無効。WebView 内にフォーカスがあるとき、Ctrl+Tab などアプリのショートカットが効かないのは既知。
- [ ] WebView2 ランタイムがない環境（または無効化して）でプレビューを開くと、案内が状態表示とペインに出て、編集は続けられる。
- [ ] 長い文書の途中までスクロールしてから編集すると、更新後も同じ位置のまま（先頭へ戻らない）。文書が短くなった場合は末尾に収まる。別の Markdown のタブへ切り替えたときは先頭から表示される（0.1.3 で修正）。
- [ ] 右ペインの境界をドラッグして幅を変えられる。2 画面・高 DPI で表示が崩れない。
- [ ] 終了時に `msedgewebview2.exe` が残らない。
