# 改善 U1〜U4 の Windows 実機確認

Wine＋Xvfb の自己診断（`linote.exe --self-test`）で通る範囲は済んでいる。ここは**実機でしか確かめられない**項目。

## U1 ファイル操作

### 開くダイアログ

- [ ] Ctrl+O の種類の既定が「すべてのファイル (*.*)」で、`.txt` 以外（`.log`、`.json`、拡張子なしなど）が最初から一覧に出る。
- [ ] 種類を「テキストファイル」にすると、txt／log／md／csv／json／xml／html／css／js／ts／rs／py／ini／toml／yaml などだけに絞られる。
- [ ] 複数選択すると、それぞれがタブで開く。
- [ ] 名前を付けて保存（Ctrl+Shift+S）の種類の既定も「すべてのファイル」。拡張子を省くと `.txt` が付く。

### ドラッグ＆ドロップ

- [ ] エクスプローラーからファイルを**本文**にドロップすると開く（カーソルが複写の形になる）。
- [ ] **タブバー**・**状態表示**・メニューの下の余白にドロップしても開く。
- [ ] 複数ファイルを一度にドロップすると、全部がタブになる。
- [ ] フォルダーをドロップしても開かず、状態表示に「フォルダーは開けません」が出る（ファイルと混在でもファイルは開く）。
- [ ] 既に開いているファイルをドロップすると、新しいタブでなく既存のタブへ移る。
- [ ] 巨大ファイル（読み取り専用ビュー）の表示中にドロップしても開く。
- [ ] 本文内で選択した文字列をドラッグして移動・複写する操作が、従来どおり動く（ファイルのドロップ対応で壊れていない）。
- [ ] 他のアプリ（ブラウザーなど）からテキストを本文へドロップすると、挿入される。
- [ ] 管理者権限で起動した Linote には、通常権限のエクスプローラーからドロップできない（Windows の仕様）ことを確認し、案内が必要か判断する。

### 最近使ったファイル

- [ ] ファイル > 最近使ったファイルに、開いた順に最大 10 件が出る。初回は「(なし)」（灰色）。
- [ ] 項目を選ぶと開く。既に開いていればそのタブへ移る。
- [ ] 名前を付けて保存したファイルも一覧に入る。
- [ ] 長いパスは中ほどが「...」で省かれ、`&` を含むパスが正しく表示される。
- [ ] 一覧のファイルを削除してから選ぶと、「見つかりません。一覧から外しました」と出て、一覧から消える。
- [ ] 再起動しても一覧が残る（`%LOCALAPPDATA%\Linote\settings.json` の `recent_files`）。存在確認のために起動が遅くならない。
- [ ] 複数のファイルを続けて開く（またはドロップする）操作の後でも、一覧が正しい順で保存される。

### 再読み込み・閉じる

- [ ] ファイル > ファイルを開き直す: 別のエディターで書き換えたファイルを、保存されている内容で開き直せる。未保存の変更がなければ確認なし。
- [ ] 未保存の変更があるときは確認が出て、「いいえ」なら何も変わらず、「はい」なら変更が失われてディスクの内容になる。
- [ ] 外部変更の警告（「外部で変更」）が出ているタブで再読み込みすると、警告が消えて上書き保存できる。
- [ ] 無題・メモのタブでは再読み込みできない旨が出る。
- [ ] ほかのタブをすべて閉じる: アクティブなタブだけが残る。未保存のタブは 1 つずつ確認が出て、「取り消し」でそこで止まる。
- [ ] すべて閉じる: 全部閉じて空の新規タブが 1 つ残る。未保存の確認が出る。

### 新しいウィンドウ

- [ ] Ctrl+Shift+N（ファイル > 新しいウィンドウ）で、別のウィンドウが新しいプロセスで起動する（タスクマネージャーで 2 プロセス）。
- [ ] 2 つのウィンドウで同じ設定・メモを使え、一方でメモを編集して閉じても他方の復元データ・メモが壊れない。
- [ ] 2 つ目のウィンドウの起動時に、1 つ目の未保存文書の復元データを「復元しますか」と尋ねない（ロック中の復元データは対象外）。

### 保存時の文字コード・改行

- [ ] ファイル > 保存時の改行 > CRLF／LF／CR: 本文の改行が変換され、ステータスバーの改行表示が変わり、タブが未保存になる。保存したファイルをバイナリエディターで見て、指定の改行だけになっている。Ctrl+Z で変換前に戻る。
- [ ] ファイル > 保存時の文字コード: UTF-8／UTF-8 (BOM 付き)／UTF-16 LE／UTF-16 BE／Shift_JIS (CP932) を選ぶと、ステータスバーの表示が変わり、タブが未保存になる。保存したファイルのバイト列が指定のとおり（UTF-16 は BOM 付き）。
- [ ] CP932 に変換できない文字（絵文字など）を含むときは、保存時に「変換できない文字」の確認が出る。
- [ ] 保存時の文字コードを変えたあと、そのファイルを Linote で開き直すと、同じ文字コード・改行で開く。
- [ ] メモのタブでは、保存時の文字コード・改行を選んでも、使えない旨が状態表示に出て何も変わらない。

### パス

- [ ] フルパスをコピー: クリップボードにフルパスが入り、メモ帳などに貼り付けられる。無題の文書では案内が出る。
- [ ] エクスプローラーで表示: エクスプローラーが開き、そのファイルが選択されている。空白・日本語・`&` を含むパスでも選択できる。

## U2 表示の改善

Wine＋Xvfb の自己診断では、設定が編集欄の Scintilla の状態（折り返しモード、右余白、ガイド線の桁、タブ幅、空白・改行の表示、拡大、文字サイズ）と巨大ファイルのビューの行番号欄に反映され、設定ファイルに保存されること、桁指定でちょうどの桁数が折り返されないことまでを確認している。見た目は実機で確かめる。

### 折り返し

- [ ] 表示 > 折り返し > ウィンドウ幅で折り返す（単語単位）: 長い行（英文）がウィンドウ幅で単語の切れ目で折り返され、ウィンドウの幅を変えると折り返しが追従する。横スクロールバーが出ない。
- [ ] 文字単位: 英単語の途中でも右端で折り返す。日本語の長い行が右端で折り返される。
- [ ] 折り返した 2 行目以降が、元の行と同じ深さのインデント（行頭の空白）で表示される。
- [ ] 指定した桁で折り返す...: 入力欄（既定 80）に 40 と入力すると、等幅フォントで半角 40 文字（`0` を 40 個）の行は折り返されず、41 個で折り返される。ガイド線が 40 桁目の右端に縦線で出る。ウィンドウを広げても 40 桁のまま。狭めると、ウィンドウ幅で折り返す。
- [ ] 桁指定で、行数が増えて行番号の桁が増えたとき（99 → 100 行、999 → 1000 行）や、拡大・縮小、フォント変更のあとでも、折り返し位置の桁が保たれる（ガイド線との位置関係が変わらない）。
- [ ] 桁指定の入力欄で 5 や abc、取り消しを入力しても設定が変わらず、状態表示に案内が出る。
- [ ] 折り返し桁のガイド線をオフにすると線が消える。桁指定以外ではそもそも線が出ない。
- [ ] 折り返しを変えたあと、別のタブに切り替えても同じ折り返しになる（全タブに適用）。再起動しても維持される。
- [ ] 折り返し有効のとき、Home／End、上下キーが表示行単位で動く（Scintilla の標準動作）。

### 書体・拡大・縮小

- [ ] 表示 > フォント...: 標準のフォント選択ダイアログが出て、書体とサイズを選ぶと本文に反映される（行番号の欄の幅も追従する）。取り消しで変わらない。再起動しても維持される。
- [ ] 既定のフォントに戻す: Cascadia Mono（なければ Consolas／MS Gothic）の 11 pt に戻る。
- [ ] Ctrl+マウスホイールで拡大・縮小でき、状態が保存される（再起動で維持）。Ctrl+Plus（日本語配列では Ctrl+;、英語配列では Ctrl+= と Ctrl+Shift+=）、Ctrl+Minus、テンキーの Ctrl+＋／−、Ctrl+0（元に戻す）が効く。
- [ ] 拡大した状態で桁指定の折り返しの桁位置がずれない。
- [ ] 高 DPI／DPI の異なるモニター間の移動で、書体の大きさ・折り返しが崩れない。

### 表示の切り替え

- [ ] 空白とタブを表示: スペースが点、タブが矢印で表示される。改行記号を表示: CRLF／LF／CR の記号が行末に出る。どちらもダーク／ライトの両方で読める色。
- [ ] 行番号を表示（オフ）: 通常のタブで行番号の欄が消える。巨大ファイル（`scripts/gen-large-fixtures.py` で作ったもの）のタブでも行番号の欄が消え、本文が左端へ寄り、選択・スクロール・検索のヒット位置がずれない。オンに戻すと両方とも戻る。隠したまま巨大ファイルを開いても隠れている。再起動で維持される。
- [ ] 現在行の強調: カーソルのある行の背景が変わる。オフにすると消える（ダーク／ライトの両方）。
- [ ] 対応する括弧の強調: `(` `)` `[` `]` `{` `}` のすぐ前後にカーソルを置くと、括弧と対応先が強調される。対応のない括弧は別の（エラー系の）強調。オフで消える。
- [ ] 表示メニューの項目の印（チェック）が現在の設定と一致する（折り返し、タブ幅、各切り替え）。

### タブ・インデント

- [ ] タブ幅 2／4／8: 開いている文書のタブ文字の幅が変わる。新しいタブ・開き直した文書にも同じ幅。再起動で維持される。
- [ ] タブをスペースで入力（オン）: Tab キーでタブ幅ぶんの位置までスペースが入る。選択範囲に Tab（Scintilla の標準でインデント）、Shift+Tab も動く。
- [ ] 自動インデント（オン）: 行頭にスペース・タブのある行の末尾で Enter すると、次の行が同じ空白で始まる。IME で確定した直後の Enter でも同様。オフにすると引き継がない。
- [ ] 日本語入力（IME）変換中の表示位置が、拡大・フォント変更のあとでもずれない。

### 設定ファイル

- [ ] `%LOCALAPPDATA%\Linote\settings.json` の `view` に変更が反映され、手で `wrap` を `"column"`、`wrap_column` を 100 に書き換えて起動すると、そのとおりに動く。不正な値（`"wrap": "x"`、`tab_width` が 3 など）は既定値として読まれ、ほかの設定は失われない。

## U3 検索と編集の改善

自動試験（`src/ui/app/selftest/integration_u3.rs`、`cargo test` の GUI 自己診断）で、強調の件数と位置、現在の一致の印、編集・Esc・タブ切り替えで消えること、ワーカー経路、20000 件の上限、検索欄なしの F3／Shift+F3／Ctrl+F3、巨大モードの F3、選択範囲内の置換、各編集コマンドと Undo 1 回、対応する括弧への移動は確認済み。次は Windows 実機で見た目と操作感を確かめる。

### 強調表示

- [ ] Ctrl+F で検索語を入力すると、入力に合わせて本文のすべての一致が琥珀色の半透明の枠で強調される。ダーク／ライトの両方で一致した文字が読める。
- [ ] 「次へ」や F3 で移った現在の一致が、ほかとは別の橙色で強調される（選択の色と重なっても分かる）。
- [ ] 検索欄の状態欄に「n / 全 m 件」が出る。0 件のとき「見つかりません」。大文字小文字・単語単位・正規表現を切り替えると件数と強調が更新される。無効な正規表現（`(`）では強調が消え、エラーが出る。
- [ ] 検索欄を閉じても強調が残る。本文にフォーカスがある状態で Esc を押すと消える。本文を 1 文字入力すると消える。別のタブへ移ると消え、戻っても残らない。
- [ ] 数万件ある文書（例: `a` を 10 万個）で、入力が固まらない。「全 20000+ 件」と出て、F3 での移動は 20000 件より先にも進める。1 MiB を超える文書でも入力が固まらない（強調は少し遅れて付く）。
- [ ] 巨大ファイル（読み取り専用のビュー）では強調されず、F3／Shift+F3 での移動だけが動く。

### F3／Shift+F3／Ctrl+F3

- [ ] 検索欄を一度も開かずに、単語の上にカーソルを置いて F3 を押すと、その単語の次の一致へ移り、強調と「n / 全 m 件」が状態表示に出る。選択範囲があれば、その文字列で検索する。Shift+F3 で前へ。
- [ ] 検索欄で検索したあと閉じて、F3／Shift+F3 で直前の条件のまま次・前へ移る。
- [ ] Ctrl+F3: 選択した文字列（なければ単語）を検索語にして次へ移る。検索欄を開くとその文字列が入っている。
- [ ] 何も選択しておらず、カーソルが空白・行頭など単語のない場所で、かつ検索条件がないとき、F3 で検索欄が開く。

### 選択範囲内の置換

- [ ] 範囲を選択し、検索欄で「選択範囲内のみ置換」にチェックして「すべて置換」: 選択範囲の中だけが置換され、置換後の範囲が選択されたままになる。Ctrl+Z 1 回で元に戻る。選択がなければ案内が出る。
- [ ] チェックを外した「すべて置換」は従来どおり文書全体を置換する。巨大ファイルではチェックボックスも無効になる。

### 編集コマンド

- [ ] Ctrl+D: 選択なしで現在の行が直下に複製される。選択ありで選択範囲が直後に複製される。Ctrl+Z 1 回で戻る。
- [ ] Ctrl+Shift+K: 現在の行（選択にかかる行すべて）が消える。最後の行（改行なし）は直前の改行ごと消える。Ctrl+Z 1 回で戻る。
- [ ] Alt+↑／Alt+↓: 行（選択にかかる行すべて）が上下に動く。先頭行で上、末尾行で下は何も起きない。Ctrl+Z 1 回で戻る。日本語 IME が有効でも効く。
- [ ] 編集 > 変換: 大文字・小文字（選択範囲。選択がなければ案内）、行末の空白の削除（選択があればその行だけ、なければ全体。件数が状態表示に出る）、タブ→スペース、行頭スペース→タブ。どれも Ctrl+Z 1 回で戻る。タブ幅を変えると変換の幅も変わる。全角文字を含む行のタブの桁（文字数で数える）が見た目と食い違うことがある点に注意。
- [ ] 編集 > 日時を挿入: `2026-11-14 09:05` の形式でローカル時刻がカーソル位置に入る。選択があれば置き換わる。
- [ ] Ctrl+]: 括弧（`( ) [ ] { }`）の上かすぐ後ろにカーソルを置いて押すと、対応する括弧へ移る。括弧がなければ状態表示に案内が出る。日本語キーボード配列で Ctrl+]（「む」のキーに当たる `]`）が効く。
- [ ] 読み取り専用の文書（巨大ファイルなど）で、行・変換の編集コマンドがメニューで灰色になる。Ctrl+D などのキーで何も起きない。
- [ ] キー割り当て: `settings.json` の `keys` で `edit.goto_matching_brace` を `Ctrl+BracketRight` と書いても `Ctrl+]` と書いても通る。

## U4 タブの操作

実機（Windows 11、可能なら 2 台以上のモニター、倍率の違う組み合わせを含む）で確認する。自己診断（`--self-test`）は、並べ替え（`move_tab` とマウスメッセージのドラッグ）、右側を閉じる、受け渡しファイルの書き込みと受け取りの確認、失敗時に元のタブを残すこと、壊れた・古いファイルの拒否を、同じプロセスの中で確かめている。新しいプロセスの起動と実際のウィンドウの動きは次を確かめる。

### 並べ替え

- [ ] タブを左右にドラッグすると、動かしている間に並びが入れ替わる。幅の違うタブ（題名の長さが違う）でも、境目で行き来してちらつかない。ドラッグしたタブが選択された状態で終わり、未保存の丸・AI の印が付いてくる。
- [ ] 少しだけ動かして離す（クリック）と並びは変わらず、そのタブが選択される。閉じるボタン（×）の押下は従来どおり閉じる。
- [ ] タブが多くてあふれている状態でも、ドラッグで見えているタブの位置へ動かせる。Esc は未対応（Alt+Tab などで捕まえ直されると、その時点の並びで終わる）。

### 外へドラッグして新しいウィンドウ

- [ ] 2 つ以上のタブがある状態で、タブをウィンドウの外（デスクトップ、別のウィンドウの上、別モニター）へドラッグして離すと、離した位置の近くに新しい Linote のウィンドウが開き、その文書が表示され、元のウィンドウのタブが閉じる。ウィンドウ内（本文の上、タイトルバーの上を含む）で離したときは移らない。
- [ ] 配置: 新しいウィンドウのタブバーが、離した位置のおおよそ真下に来る。別モニター（左・上・右・下、負の座標のモニターを含む）へ離すと、そのモニターの作業領域の中に収まり、画面外へはみ出さない。タスクバーに隠れない。
- [ ] 倍率の違うモニターへ移すと、新しいウィンドウの文字・タブ・ステータスバーが適切な大きさで表示される（ぼやけない。ウィンドウの大きさが極端にならない）。
- [ ] 種類ごと: 保存済みのファイル（新しいウィンドウで同じファイルが開く）、巨大ファイル（読み取り専用のビューで開く）、メモ（同じ名前のメモが開く。直前の編集も入っている）、未保存の変更があるファイル（変更が入ったまま開き、タブに未保存の丸が付く。文字コード・改行がステータスバーで元と同じ）、無題（本文・未保存）、クリップボード由来。新しい側で保存・名前を付けて保存ができる。
- [ ] 未保存の文書を移した直後に、新しいウィンドウを強制終了（タスクマネージャー）して再び Linote を起動すると、復元の確認が出て内容を取り戻せる。元のウィンドウには移した文書のタブが残っていない。
- [ ] 失敗: 新しいウィンドウが起動する前に `%LOCALAPPDATA%\Linote\handoff\` を覗くと受け渡しファイルがあり、起動後に消える。`linote.exe` をアンチウイルスなどで起動できなくした環境、または起動した直後にタスクマネージャーで新しいプロセスを終了させた場合、最長 15 秒以内に「新しいウィンドウへ移せませんでした。元のタブはそのまま残しています」と出て、元のタブが残る。
- [ ] 移している間（起動に数秒かかる環境）に元のタブを編集すると、「元のタブは閉じずに残しました」と出て、タブが残る。
- [ ] タブが 1 つだけのときは、外へドラッグしても何も起きない（状態表示に「タブが 1 つだけのときは…」）。
- [ ] 手動: `linote.exe --adopt <壊れたファイル>` で起動すると、起動時のダイアログに理由が出て、空の無題で開く。`--pos 100,100` でそこに置かれる。

### 右クリックメニュー

- [ ] タブを右クリックすると、そのタブが選択され、閉じる／ほかのタブを閉じる／右側のタブを閉じる／新しいウィンドウに移動／フルパスをコピー／エクスプローラーで表示、が出る。タブが 1 つだけなら「ほかのタブ…」「新しいウィンドウに移動」が灰色、一番右のタブでは「右側…」が灰色、ファイルでない文書ではパス関連が灰色。
- [ ] 「右側のタブを閉じる」: 未保存の文書は 1 つずつ確認が出て、取り消すとそこで止まる。「新しいウィンドウに移動」は既定の位置に新しいウィンドウが開く。
- [ ] ファイルメニューにも「右側のタブを閉じる」「新しいウィンドウに移動」が出て、アクティブなタブに働く。

## U5 印刷（基本）

実機（Windows 11、実プリンターと「Microsoft Print to PDF」の両方）で確認する。自己診断（`--self-test`）は、印刷コマンドの有効・無効（巨大ファイルでは無効で案内が出る）、印刷の選択肢の保存、メモリ上の 96 dpi A4 のビットマップに対するページ区切りの計算・1 ページの描画（余白が白のまま、ヘッダー・フッターの罫線、本文）、印刷中だけ設定が変わって元に戻ることを確かめている。Wine にはプリンターがなく、字形の描画も確かめられないため、次は実機で確認する。

- [ ] `Ctrl+P`（ファイル > 印刷...）で Windows の印刷ダイアログが開く。プリンター、部数、ページ範囲、選択範囲のみ（選択がなければ「選択した部分」は灰色）が使える。取り消すと何も起きない。
- [ ] 「Microsoft Print to PDF」で数十ページの文書を印刷し、PDF のページ数、ヘッダー（ファイル名または無題などのタブ名と日時）、フッター（`n / m`）、罫線、余白（既定 20 mm）を確認する。ページ範囲「2〜3」を指定すると、その 2 ページだけが出て、フッターは「2 / m」「3 / m」（全体の通し番号）になる。
- [ ] 選択範囲のみ: 一部を選んで印刷すると、その範囲だけが出て、ページ数もその範囲の分になる。
- [ ] 長い行は紙の幅で折り返して印刷される（画面で折り返しをオフにしていても）。画面の拡大率（Ctrl+ホイール）は印刷の文字サイズに影響しない。日本語（全角）、タブ、構文着色のある文書でも崩れない。
- [ ] ファイル > 印刷の設定: 「色分けして印刷」をオフにすると白黒、オンにすると色つき（背景は常に白。ダークテーマでも）。「行番号を印刷」で行番号が付く／消える（画面の行番号の設定とは独立）。「ヘッダー」「フッター」のオフで帯が消え、本文が広がる。メニューのチェックが設定を反映し、再起動後も保たれる。
- [ ] ファイル > ページ設定...: 用紙（A4／Letter など）、向き（横）、余白を変えて OK すると、次の印刷（と再度のページ設定）に反映される。再起動後も用紙・向き・余白が保たれる。取り消すと変わらない。余白を極端に大きくして印刷すると、案内が出て印刷しない。
- [ ] 実プリンター: 余白が用紙の端から測られる（プリンターの印刷できない端の分を引いても、設定どおりの余白になる）。複数部数、両面、用紙トレイなどの設定が印刷ダイアログどおりに効く。
- [ ] 巨大ファイル（読み取り専用）のタブでは、ファイル > 印刷... が灰色で、`Ctrl+P` で「巨大ファイル（読み取り専用）は印刷できません…」と状態欄に出る。ページ設定は使える。
- [ ] プリンターが 1 台もない環境（または「Microsoft Print to PDF」を無効にして）で `Ctrl+P` すると、その旨が状態欄に出て、アプリは落ちない。
- [ ] 印刷中に画面が応答しない時間があっても、完了後に元の表示（行番号の欄の幅、色、折り返し）に戻る。
