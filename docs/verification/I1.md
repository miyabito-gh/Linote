# I1 統合の Windows 実機確認（🪟確認1 の項目）

対象: ファイルの開く・保存、文字コード、復元、メモ、クリップボード、メニューとショートカット。
Wine＋Xvfb の自己診断（`linote.exe --self-test`）で通る範囲は済んでいる。ここは**実機でしか確かめられない**項目。
`LINOTE_DATA_DIR` を設定すると、設定・メモ・復元データの置き場所を変えられる（試験用）。

## 1. 起動と表示

- [ ] 起動が速い（メモ一覧・WebView2・Grep を読み込まない）。タスクマネージャーで WebView2 関連プロセスが出ない。
- [ ] メニューバー（ファイル／編集／検索／表示／メモ）が出る。ニーモニック（Alt+F など）で開く。
- [ ] 各項目の右にキーが表示される。メニューを開くと、使えない項目（読み取り専用の文書での切り取り・貼り付けなど）が灰色になる。
- [ ] 高 DPI・2 画面で、メニュー・ダイアログの文字がぼやけず、切れない。
- [ ] 表示 > テーマを切り替え（システム → ライト → ダーク）が、タイトルバー・タブ・メモの小窓に反映される。再起動後も保たれる（`settings.json` の `theme`）。

## 2. ファイルを開く・保存（共通ダイアログ）

- [ ] Ctrl+O で共通のファイルダイアログが開く。複数選択すると、それぞれタブになる。
- [ ] 同じファイルをもう一度開くと、新しいタブでなく既存のタブへ移る。
- [ ] 取り消しで何も起きない。存在しない・権限のないファイルは、原因別の文言が状態表示に出る。
- [ ] Ctrl+S: ファイルのある文書は上書き。無題・クリップボードのタブは「名前を付けて保存」ダイアログになる。
- [ ] Ctrl+Shift+S: 既存ファイルを選ぶと上書きの確認が出る。保存後、タブの名前と言語（拡張子）が変わる。
- [ ] 保存中も UI が固まらない（数十 MiB のファイルで確認）。保存後にタブの未保存の丸が消える。
- [ ] 保存の直後に編集を続けても、その編集分は未保存のまま残る。

## 3. 文字コード・改行の保持

- [ ] CP932（Shift_JIS）＋CRLF のファイルを開き、編集して保存しても、CP932・CRLF のまま（バイナリ比較）。ステータスバーに `Shift_JIS (CP932)` と `CRLF`。
- [ ] UTF-8 BOM 付き・LF のファイルが、BOM 付き・LF のまま保存される。UTF-16 LE/BE（BOM 付き）も同様。
- [ ] 判定に自信がないファイルを開くと、文字コードを指定するよう促す状態表示が出る。
- [ ] 読めないバイトを含むファイルを開くと「置き換えて表示している」警告が出る。そのまま上書きしようとすると確認が出て、断ると書き込まれない。
- [ ] ファイル > 文字コードを指定して開き直す（UTF-8／UTF-8 BOM 付き／UTF-16 LE／UTF-16 BE／CP932）で本文が変わる。未保存の変更があるときは破棄の確認が出る。タブは末尾に作り直される（既知）。
- [ ] CP932 で表せない文字（絵文字など）を含めて保存すると、文字と位置を示す確認が出る。断ると何も書かれない。承知すると `?` に置き換わって保存される。
- [ ] ¥（U+00A5）・‾（U+203E）・−（U+2212）が、CP932 では変換できない文字として扱われる（黙って別の文字に化けない）。

## 4. 外部変更

- [ ] ファイルを開いたまま、別のエディターで内容を変えて保存し、Linote をクリックして前面に戻す → 状態表示で知らせる。
- [ ] その状態で Ctrl+S → 上書きされず、別名保存を案内する確認が出る。「はい」で保存先を選べる。
- [ ] 別名保存後は外部変更の表示が消え、元のファイルは変更されていない。
- [ ] 別のタブへ切り替えたとき（そのタブのファイルが変更されていた場合）も検知する。
- [ ] ファイルを削除・移動した場合も同様に知らせる。
- [ ] 読み取り専用属性のファイルへの保存が、原因を示して失敗する（元ファイルは無傷）。他のプログラムが開いている（共有違反）場合も同様。

## 5. 未保存のタブを閉じる・終了

- [ ] 未保存のタブを閉じる（×、Ctrl+W、中クリック）と「保存／保存しない／キャンセル」（はい／いいえ／キャンセル）が出る。
- [ ] 「はい」: 名前のない文書は保存先を尋ね、保存が終わってから閉じる。保存先の選択を取り消すと閉じない。
- [ ] 「いいえ」: 閉じる。復元データも消える（次回起動で復元を尋ねられない）。
- [ ] 未保存の文書が複数ある状態でウィンドウを閉じる → 文書ごとに確認が出る。途中でキャンセルすると終了しない。「保存しない」と答えた文書は、終了時に破棄される。
- [ ] メモのタブは尋ねずに保存して閉じる。

## 6. 復元

- [ ] 編集して数秒待つ（最後の編集から約 2 秒、続けて編集していても 30 秒以内）と、`%LOCALAPPDATA%\Linote\recovery` に復元データができる。
- [ ] タスクマネージャーでプロセスを強制終了 → 再起動すると、復元するか尋ねる。「はい」で未保存のタブとして開く（元のファイルは書き換わっていない）。「いいえ」で破棄、「キャンセル」で次回また尋ねる。
- [ ] 元ファイルが復元データの後で変更されていた場合、復元後に上書き保存できず、別名保存を案内する。
- [ ] 2 つ目のウィンドウ（別プロセス）を起動しても、1 つ目が所有する復元データについて尋ねられない。
- [ ] 正常に終了（保存または「保存しない」）した後は、復元データが残らない。

## 7. メモ

- [ ] Ctrl+Shift+M（メモ > メモの一覧）で小窓が出る。初回に一覧を読み込む。もう一度押すと閉じる。Esc でも閉じ、本文にフォーカスが戻る。
- [ ] メモを選ぶとタブで開く（同じメモは同じタブ）。編集して 1〜2 秒待つと自動で保存される（タブの未保存の丸が消える）。
- [ ] Ctrl+S でメモとして保存される。名前の変更（メモ > メモの名前を変更）がタブと一覧に反映される。
- [ ] 2 つのウィンドウで同じメモを編集して保存すると、後から保存した側は「（競合）」の別メモとして残り、状態表示で知らせる。
- [ ] 編集した直後にウィンドウを閉じても、メモの内容が失われない。
- [ ] ダーク／ライトの切り替えと DPI 変更が小窓に反映される。

## 8. クリップボードとグローバルホットキー

- [ ] 他のアプリを前面にして Ctrl+Alt+V → Linote が前面に出て、クリップボードの内容が未保存の新しいタブになる。
- [ ] Linote を最小化した状態でも、復元されて前面に出る。
- [ ] テキスト以外（画像のみ、リッチテキストのみ）のときは「クリップボードにテキストがありません」と出て、タブは作られない。
- [ ] 他のアプリが同じキーを使っている場合、起動時に競合の状態表示が出る（動作は続く）。`settings.json` の `keys["clipboard.new_tab"]` を変えて再起動すると反映される。空文字列で無効になる。`Win+` を含む割り当ても試す。
- [ ] 前面化に失敗した場合（フォーカスの奪い合い）に、その旨が状態表示に出る。
- [ ] Linote がアクティブなときの Ctrl+Alt+V（アプリ内のキー）も同じ動作をする。

## 9. 編集・ショートカット

- [ ] Ctrl+N／O／S／Shift+S／W、Ctrl+Z／Y、Ctrl+X／C／V、Ctrl+A、Ctrl+G、Ctrl+Tab／Ctrl+Shift+Tab が効く。メニューの項目でも同じ動作。
- [ ] 日本語 IME の変換中（未確定の文字）に、Ctrl や Alt を含むキーを押しても、確定前の文字が壊れない。IME の切り替え（半角/全角、Ctrl+Space など）が奪われない。
- [ ] Ctrl+G で入力欄が出る。全角数字・桁区切りも受け付ける。範囲外は最終行へ。不正な入力では動かず、状態表示が出る。
- [ ] 矩形選択: Alt+ドラッグ、Alt+Shift+矢印で矩形選択になり、一括入力・コピー・貼り付けができる。
- [ ] 貼り付けた改行が、その文書の改行（CRLF/LF）にそろう。
- [ ] 読み取り専用の文書で、切り取り・貼り付け・元に戻すがメニューで灰色になる。

## 10. 設定ファイル

- [ ] `settings.json` がなくても起動できる。テーマを切り替えると作られる。
- [ ] `settings.json` を壊す（`{` だけにするなど）→ 起動時に「設定ファイルを読めません」と状態表示が出て、既定の設定で動く。テーマを切り替えても**ファイルは上書きされない**（壊れたまま残る）。
- [ ] `keys` で割り当てを変える（例: `"file.save": "Ctrl+Alt+S"`）と、メニューの表示とショートカットに反映される。誤った表記・重複は状態表示で知らせ、既定値で動く。
- [ ] `LOCALAPPDATA` を使えない環境でも起動でき、メモ・復元・設定の保存が使えない旨が出る（編集は続けられる）。

## 既知の制限（I1 の範囲外・仕様どおり）

- 検索・置換・Grep、巨大ファイルのビュー、Markdown プレビューのメニュー・ショートカットは I2 で統合する。256 MiB を超えるファイルは、巨大ファイルのビューの統合（I2）までは開けない（メッセージで知らせる）。
- 文字コードの開き直しでは、タブが末尾に作り直される。
- メモの競合保存で別メモに切り替わったとき、タブの内部の種類に持つ ID は開いたときのまま（保存領域とのやり取りは正しい ID を使う）。
