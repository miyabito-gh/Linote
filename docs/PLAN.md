# Linote 実装計画とエージェント・オーケストレーション

要件の正本は [requirements.md](requirements.md)。この文書は作業分担・依存関係・進捗の管理に使う。状態の更新はオーケストレーター（統括エージェント）が行う。

## 1. オーケストレーションの原則

### 役割

- **オーケストレーター（統括、Opus）**: 計画、タスク分解、作業指示書の作成、レビュー、統合、テスト、`main` への push、この文書の更新。
- **ワーカーエージェント**: 割り当てられたモジュールの実装。担当パス以外は編集しない。
- **モデルの使い分け**
  - **Fable**: データ消失・破損、並行性、セキュリティに関わる部分の設計・実装・レビュー。
  - **Opus**: 通常の実装と統合。
  - **Sonnet**: 定型作業（骨組み、テストデータ生成、配布スクリプト）。

### 文脈の受け渡し（リポジトリ内の文書で行う）

新しく起動したエージェントは会話を知らないため、必要な文脈はすべてリポジトリ内に置く。

| ファイル | 役割 | 更新者 |
|---|---|---|
| `CLAUDE.md` | ビルド・テストのコマンド、規約、触ってはいけない箇所 | オーケストレーター |
| `docs/requirements.md` | 要件の正本 | オーケストレーター（利用者合意時のみ） |
| `docs/architecture.md` | 共通の取り決め（型・インターフェース）と設計判断の記録 | C0 で Fable が作成、以後オーケストレーターが管理 |
| `docs/PLAN.md` | この文書。タスク、依存、状態 | オーケストレーター |
| `docs/tasks/<ID>.md` | 各タスクの作業指示書 | オーケストレーター |

**作業指示書の項目**: 目的／担当パス（これ以外は編集しない）／使う取り決め／合格条件となるテスト／実行コマンド／報告形式（変更内容、テスト結果、未解決点、取り決めの変更が必要か）。

### 競合回避

- モジュールのディレクトリごとに担当は1人。
- 共有ファイル（`Cargo.toml`、`build.rs`、`src/main.rs`、コマンド登録表）はオーケストレーターだけが編集する。各モジュールは登録関数を公開し、つなぎ込みは統合時に行う。

### git

- ワーカーは自分の作業ツリー（worktree）のブランチでコミットのみ行い、push しない。
- オーケストレーターがローカルでマージし、全体の品質関門を通してから `main` へ直接 push する（利用者合意済み）。
- リポジトリの git 通信は同時2本まで。push はオーケストレーターが順に行う。
- クラウドのコンテナは消えることがあるため、区切りごとに push してこの文書を更新する。

### 同時実行

ワーカーは同時に最大3つ。レビュー・統合の負荷と git 通信の上限に合わせる。

### 品質関門

1. 全タスク共通: `cargo fmt --check`、`cargo clippy --target x86_64-pc-windows-gnu -- -D warnings`、`cargo test --target x86_64-pc-windows-gnu`（Wine で実行）。
2. 単体EXE検査: EXE が読み込む DLL に Windows 標準以外が含まれないこと。
3. 重要モジュール（表で **太字** の担当）は、実装者とは別の Fable エージェントがレビューする。
4. 段階の終わりに、利用者へ Windows 実機での確認項目を渡す（🪟）。

### 失敗時の扱い

- 「詰まった」報告は指示書を直して1回だけ再実行する。それでも進まなければ利用者に相談する。
- 統合後にテストが壊れたら、そのブランチを差し戻す。
- 取り決めの変更が必要になったら作業を止め、Fable が `architecture.md` を改訂してから影響範囲をやり直す。

### クラウドで確認できないこと

IME、DPI、WebView2 の表示、グローバルショートカット、前面表示、性能計測は Windows 11 実機で利用者が確認する。保存・復元・文字コード・検索・索引は画面なしでテストできる作りにし、品質の大部分をそこで担保する。

## 2. 作業の流れ

```
W0 土台 ─┬─ 事前検証 S1・S2（並行）
         └─ C0 共通の取り決め（Fable）
               │
W1 通常編集 ── A ∥ B ∥ T1 → I1 統合 → R1 レビュー → 🪟確認1
               │
W2 メモ・復元 ── D ∥ E ∥ F → I2 → R2 → 🪟確認2
               │
        ┌──────┴──────┐ （W3 と W4 は独立。並行可）
W3 Markdown       W4 巨大ファイル・Grep
 G ∥ H → R3        J ∥ K → L → I4 → R4
        └──────┬──────┘
W5 配布・性能 ── N → 🪟性能計測 → O 最終レビュー
（次の版）W6 MCP ── P1 中継・stdio ∥ P2 認可 → P3 GUI確認・表示 → R6
```

### 2026-11-14 0.1.3 既知の課題の修正（ファイル ID・プレビューのスクロール）
