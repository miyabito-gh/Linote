# Linote 仕様書（実装どおりの動作）

この文書は、現在のコードが実際に行う動作を利用者向けにまとめたものです。計画や要件ではなく**実装の事実**を書きます。要件（`docs/requirements.md`）との違いは第 17 章に集めました。コードから確認できなかった点は「未確認」と書いています。

## 1. 概要と動作環境

- Windows 11 x64 向けの軽量テキストエディタです。EXE 1 つ（`linote.exe`）で動き、Windows 標準以外の DLL を必要としません。`WebView2Loader.dll` も使いません（Markdown プレビューは自前のローダーで WebView2 ランタイムを探します）。
- 通常編集の部品は Scintilla 5.4.1、構文着色は Lexilla 5.3.0 を組み込んでいます。
- 起動を軽くするため、WebView2（プレビュー）、メモ一覧、検索・Grep の小窓、巨大ファイルの処理は、初めて使うときに初期化します。
- コマンドラインに渡したパスは、起動時にそれぞれタブで開きます。開くファイルも受け渡し（`--adopt`）もなければ、前回のタブを開き直します（1.1）。それもなければ**文書 0 件で起動**し、無題の文書は作りません。
- 高 DPI は PerMonitorV2 に対応し、DPI が変わるとレイアウトと書体を作り直します。

### 配布形式

従来のポータブル ZIP に加え、`linote-<版>-win-x64-setup.exe` を提供します。
インストーラーも64ビット版で、管理者権限なしに `%LOCALAPPDATA%\Programs\Linote`（変更可）へ EXE と第三者ライセンスを導入し、現在ユーザーのスタートメニューと「インストールされているアプリ」に登録します。
アンインストールは導入したファイル・ショートカット・登録だけを削除し、設定・メモ・復元データ、および導入先へ追加した別のファイルは残します。コード署名は未実施です。
生成手順は `scripts/package-installer.sh`（NSIS 3.11 以降）で、SHA-256 ファイルも出力します。

### データ保存場所

既定は `%LOCALAPPDATA%\Linote` です。環境変数 `LINOTE_DATA_DIR`（絶対パス）を設定すると、保存場所をその場所に差し替えます。ディレクトリとファイルは**初めて必要になったときに作ります**（パスを求めるだけでは何も作りません）。

| 場所 | 内容 |
|---|---|
| `settings.json` | 設定（第 15 章）。設定を変更して保存するときに初めて作ります（終了時のウィンドウ位置の記録でも作ります） |
| `session.json` | 前回のタブの記録（1.1）。正常終了のときに書きます |
| `memos\` | 一時メモ（1 メモ 1 ファイル `<id>.memo`、UTF-8 の JSON）と排他用の `.lock` |
| `recovery\` | 未保存変更の復元データ。壊れたものは `recovery\quarantine\` へ隔離 |
| `handoff\` | 別ウィンドウへ移すタブの受け渡しファイル（`handoff-<pid>-<時刻>-<連番>.json`）。受け取られると消え、残りは 24 時間後の次の移動で片付けます（4.8） |
| `mcp\` | 次の版の MCP 用（現在は何も作りません） |

保存場所を決められない環境（`LOCALAPPDATA` がない、絶対パスでない）では、起動時に「メモ・復元データ・設定の保存は使えません」と状態欄に出し、編集は続けられます。

### 1.1 起動・終了とウィンドウ（V1）

- **文書は 0 件でもよい**: 無題の文書を無条件には作りません。起動時に開くものがない、最後のタブを閉じた、「すべて閉じる」を実行した、開くのに失敗した、のいずれでも文書 0 件になります（`新規` やタブバーのダブルクリックで作れます）。読み込みは非同期なので、開く処理が進行中のあいだも無題は作りません（別ウィンドウへ移したタブを受け取る新しいプロセスで、余分な無題ができる不具合の修正）。
- **0 件のときの画面**: 編集欄を隠し、本文の場所にテーマの色で案内を描きます。「Ctrl+N 新規　Ctrl+O 開く」（実際のキー割り当てを表示。割り当てがなければメニューの案内）と、最近使ったファイル最大 5 件です。最近使ったファイルはクリックで開けます（マウスカーソルが手の形になり、存在しなければ従来どおり一覧から外します）。ステータスバーの文書情報は空、ウィンドウの題名は「Linote」になります。
- **文書を前提とするコマンド**（保存、名前を付けて保存、閉じる、印刷、編集、行へ移動、検索・置換・次へ・前へ、Markdown プレビュー、次・前のタブなど、対象が文書のもの）は、0 件のときメニューが無効になり、ショートカットは何もしません。新規、開く、最近使ったファイル、新しいウィンドウ、メモ、Grep、表示の設定などは使えます。
- **前回のタブの復元**: 正常に終了するとき（すべての確認を通って終了するとき）に、ファイルのある通常文書と巨大文書のパス、タブ順、アクティブなタブ、カーソル位置（バイト）、表示の先頭行を `session.json` に原子的に書きます。無題・メモ・クリップボード由来は対象外です（未保存の内容は復元データが担います）。起動時に引数も `--adopt` もなければ、これを読み、存在するファイルを既存の非同期の読み込みで開いて、順序・カーソル・アクティブなタブを戻します（存在しないものは黙って飛ばします。読み込みの完了順は不定なので、完了するたびに記録の順へ並べ直し、前面にするのは前回アクティブだったタブだけです）。複数のウィンドウでは、最後に終了したウィンドウの内容が残ります。記録が壊れていれば何もしません。設定 `restore_session`（既定 `true`）が `false` なら、読みも書きもしません（既にある `session.json` はそのまま残ります）。確認なしの終了（自己診断）では書きません。
- **ウィンドウの位置と大きさ**: 終了時に `GetWindowPlacement` の通常状態の矩形と最大化の有無を `settings.json` の `window` に書き、起動時に戻します。記録の位置が画面外（モニターを外したなど）なら、いちばん近いモニターの作業領域の内側に収め、作業領域より大きければ縮めます。`--pos` で位置を指定された新しいウィンドウ（タブの切り離し）は、記録を使わず指定の位置を優先します。壊れた設定ファイルのときは書きません。
- **Alt を離したときのメニュー**: Alt＋ドラッグ、Alt＋Shift＋矢印など、Alt を他の操作に使ったあとで Alt を離しても、メニューバーへフォーカスを移しません（その `WM_SYSKEYUP` を既定の処理に渡しません）。Alt だけを押して離したときは従来どおりメニューが有効になります。

## 2. 画面構成

上から次の順です。

1. **メニューバー**: ファイル／編集／検索／表示／メモ（第 14 章）。
2. **タブバー**: 独自描画。未保存の文書は小さな丸で示し、マウスが乗ると閉じるボタン（×）に替わります。中クリックで閉じます。タブのない場所をダブルクリックすると新規文書を作ります。タブバー上のマウスホイールで前後のタブへ移れます（上で左、下で右。端では止まります）。タブはドラッグで並べ替えられ、ウィンドウの外へドラッグして離すと新しいウィンドウに移ります。右クリックでタブのメニューが出ます（4.8）。ファイルをタブバー・本文・状態表示のどこにドロップしても開けます（4.6）。選択中のタブは本文と同じ背景で、上端にアクセント色の細い線が付きます。
3. **本文**: Scintilla（通常編集）または巨大ファイル用の読み取り専用ビュー（文書が 0 件のときは隠れて、案内を描きます。1.1）。行番号、矩形選択（Alt+ドラッグ、Alt+Shift+矢印、編集 > 矩形選択）、複数選択に対応します。既定のタブ幅は 4、書体は Cascadia Mono → Consolas → MS Gothic のうち最初にあるもの（11 pt）、既定では折り返しません。折り返し・書体・文字サイズ・拡大・空白や改行の表示・行番号・現在行や括弧の強調・タブ幅・自動インデントは表示メニューで変え、設定に保存します（13.1）。
4. **ステータスバー**: 左に短い状態表示（「保存しました」など。警告は色が変わります）。右に、`読み取り専用`／`外部で変更`／`AI の変更あり`（現在 AI 機能はないため出ません）、`行 N, 列 M`（選択があれば `(N 文字選択)`）、言語名、文字コード（BOM 付き UTF-8 は `UTF-8 (BOM)`）、改行形式（CRLF／LF／CR）。ステータスバーの項目をクリックしたときの動作は未確認です。
5. **右ペイン**（Markdown プレビューを開いたときだけ）: 本文との間のスプリッターで幅を変えられます。

検索・置換・Grep の小窓、メモの小窓は、メインウィンドウに所有された別ウィンドウです。閉じると本文にフォーカスを戻します。ウィンドウのタイトルバーの表示規則は未確認です。

## 3. 文書の種類と可能な操作

| 種類 | 作り方 | タブ名 | 編集・Undo | 保存 | 名前を付けて保存 | 未保存復元 | 構文着色 | プレビュー |
|---|---|---|---|---|---|---|---|---|
| 通常（ファイル） | 開く、起動引数 | ファイル名 | 可 | 上書き保存（`Ctrl+S`） | 可 | 対象 | 拡張子で決定 | `.md`／`.markdown` のみ |
| 新規（未保存） | `Ctrl+N` | 無題 / 無題 N | 可 | 保存先を尋ねる | 可 | 対象 | なし | 保存して `.md` になれば可 |
| メモ | メモの小窓 | メモ名 | 可 | メモとして保存（自動保存あり） | ファイルへ書き出し（メモは残る） | 対象外（メモ自体が自動保存） | なし | 不可（未確認） |
| クリップボード由来 | `Ctrl+Alt+V` | クリップボード N | 可 | 新規と同じ | 可 | 対象 | なし | 新規と同じ |
| 巨大（読み取り専用） | 大きいファイルを開く | ファイル名 | 不可 | 不可 | 不可 | 対象外 | なし | 不可 |

- 外部変更を検知した通常ファイルは、上書き保存だけが無効になります（別名保存は可能）。
- 同じパスのファイルを開こうとすると、既存のタブに切り替えます。
- 行へ移動（`Ctrl+G`）、検索、範囲コピーは全種類で使えます。

## 4. ファイルを開く・保存

### 4.1 開くときの文字コード判定

編集中の本文は常に UTF-8 です。ファイルの文字コードは次の順で判定します。

1. **BOM**（UTF-8／UTF-16 LE／UTF-16 BE）があればそれ。確定。
2. バイト列に **NUL を含む**場合は、BOM なし UTF-16（LE／BE）らしさを調べる（推定）。
3. 全体が **UTF-8 として妥当**ならそれ（ASCII のみ、または多バイト文字を含む）。
4. UTF-8 として不正で **CP932 として妥当**ならそれ（推定）。
5. どれにも当てはまらなければ UTF-8 とみなす（信頼度は低）。

判定の結果に応じた通知:

- 読めないバイトがある場合は、「�」（U+FFFD）に置き換えて表示し、状態欄に件数と「文字コードを指定して開き直す」を案内します。この文書を保存しようとすると、「元に戻せません。保存しますか？」と確認します。
- 判定の信頼度が低い場合は、判定できなかった旨と、指定して開き直す方法を状態欄に出します。

**文字コードを指定して開き直す**（ファイルメニュー）: UTF-8／UTF-8 (BOM 付き)／UTF-16 LE／UTF-16 BE／Shift_JIS (CP932) から選びます。未保存の変更があるときは「開き直すと失われます」と確認します。まだファイルになっていない文書は開き直せません。開き直す間に文書が編集された場合は開き直しを中止します。巨大ファイル（下記の切り替え条件以上）は開き直せません。

### 4.2 保存での保持

- **文字コード・BOM・改行形式**は開いたときの形式のまま保存します。本文中の改行は変換しません。新しく入力する改行の形式は、開いたときに最も多かった形式です（同数なら CRLF、LF、CR の順。改行のないファイルは、新規と同じく CRLF）。
- 新規文書の既定は UTF-8（BOM なし）・CRLF です。設定 `new_file`（15 章、設定画面の「ファイル」ページ）で、文字コード（UTF-8／UTF-8 (BOM 付き)／Shift_JIS (CP932)／UTF-16 LE・BE（BOM 付き））と改行（CRLF／LF）を変えられ、無題の文書（ファイル > 新規、タブバーのダブルクリック、0 件状態からの新規）とクリップボード由来の新しいタブに適用します（クリップボードの内容に改行があれば、改行は内容で最も多いものを優先）。メモは対象外（UTF-8 固定）。すでに開いている文書は変わりません。
- 「UTF-8 (BOM 付き)」で開き直した場合は、保存時に BOM を付けます。

### 4.3 変換できない文字

CP932 で保存するときだけ起こりえます（UTF-8／UTF-16 は全文字を表せます）。次の文字は「変換できない」として扱います。

- CP932 の表にない文字。
- 書き出すと別の文字に化ける 3 文字: `¥`（U+00A5）、`‾`（U+203E）、`−`（U+2212）。
- 外字（U+E000〜U+E757）は書き出せます。

保存の前に、最初の 5 件（文字と行・桁）と残りの件数を示して「`?` に置き換わります。保存しますか？」と確認します。承諾すれば `?` に置き換えて保存し、断ると保存を中止します（UTF-8 などで保存し直す案内を出します）。一覧は最大 1000 件で打ち切ります。

### 4.4 安全な保存

- 元ファイルを直接書きません。同じフォルダーの一時ファイルに書いて同期し、`ReplaceFileW` などで置換します。失敗・中止時は一時ファイルを消し、元ファイルは変わりません。
- 保存の直前と置換の直前に、ディスク上の状態（長さ・更新時刻・ファイル ID）が開いたときの控えと同じかを確かめます。
- **読み取り専用の属性**が付いたファイルへの上書きは失敗します（属性を外して書くことはしません）。失敗の原因は画面に表示します。保存先がフォルダーの場合も失敗します。
- 保存はバックグラウンドで行います。保存中に保存を重ねて実行すると「保存中です」と表示します。
- 保存に成功したら、対応する復元データを削除します。読み込み時の不正バイト置換の警告は復元後も保持し、保存失敗・キャンセルでは解除しません。
- 保存先の選択ダイアログで既存ファイルを選んだ場合の上書き確認は、ダイアログ側が行います。

### 4.5 外部変更の検知

開いたとき・保存したときのファイルの長さ・更新時刻・ファイル ID を控え、次のときに取り直して比べます。

- ウィンドウが前面に戻ったとき。
- 別のタブに切り替えて、そのタブが表示されたとき。
- 保存の直前。
- 復元データから文書を復元したとき。

既定の `external_change: "notify"` では、変更または削除を検知すると、その文書の上書き保存を止め、状態欄に「上書きせず、名前を付けて保存で別に保存してください」と警告し、ステータスバーに「外部で変更」を出します。保存を試みたときは「別の名前で保存しますか？」と確認します。**内容の比較はしません**。長さ・更新時刻に加えてファイル ID（ボリュームとファイルの番号）も控えるので、別のファイルで置き換える形の書き換えは、長さと更新時刻が同じでも検知します。同じファイルをその場で同じ長さに書き換え、更新時刻の刻みの中に収まった場合は検知できません。

`external_change: "reload_if_clean"` では、未保存の変更がない通常文書を非同期で読み直します。同じタブ・文書 ID と、開いていた文字コードを使い、カーソルの行・列と先頭表示行をできるだけ保ちます（短くなった場合は収めます）。成功すると状態欄で「「名前」をディスクから読み直しました」と知らせます。読み込み中に編集されたら結果を反映せず、通知に切り替えて本文を保護します。未保存の文書、削除・移動された文書は通知のままで、巨大文書は自動読み直しの対象外です。

### 4.6 開くための操作（U1）

- **開くダイアログ**（Ctrl+O）: 種類は既定が「すべてのファイル (*.*)」で、ほかに「テキストファイル」（`txt log md markdown csv tsv json xml html htm css js ts rs c h cpp hpp cs java py ps1 bat cmd sql ini toml yaml yml cfg conf properties`）を選べます。複数選択すると、それぞれがタブになります。「名前を付けて保存」も同じ種類の一覧で、既定は「すべてのファイル」です（拡張子を省くと `.txt` が付きます）。
- **ドラッグ＆ドロップ**: エクスプローラーからウィンドウにファイルをドロップすると開きます（複数可）。ドロップ先はタブバー、状態表示、本文のどこでもよく、本文への転送は同梱の Scintilla に加えた小さな修正（`third_party/VENDORED.md`）で行います。フォルダーは開かず、状態表示に「フォルダーは開けません（無視しました）: 名前」と出します。既に開いているファイルはそのタブへ移ります。テキストのドラッグ移動・ドロップ（本文内）は従来どおりです。
- **最近使ったファイル**（ファイル > 最近使ったファイル）: 既定 10 件（`recent_files_max` で 0〜30 件）、新しい順。ファイルを開いたとき、名前を付けて保存したときに先頭へ入れ（同じパスは大文字小文字を区別せず 1 件）、`settings.json` の `recent_files` に保存します。起動時には存在確認をしません。存在しないものを選ぶと、ダイアログで知らせて一覧から外します。メニューは1〜9件目がアクセスキー付き（`&1`〜`&9`）、10件目以降は番号なしで、60 文字を超えるパスは中ほどを「...」にします。壊れた設定ファイルがあるときは、一覧はその起動の間だけ保ち、書き込みません。
- **ディスクから再読み込み**（`file.reload`）: ファイルを読み直します（文字コードは自動判定）。未保存の変更があれば破棄の確認を出し、断ると何も変えません。外部変更の検知後に変更を取り込む手段にもなります。メモ・無題・巨大ファイルでは使えません。読み直すと元のタブは閉じ、新しいタブで開きます（文字コードを指定して開き直すのと同じ動作）。
- **新しいウィンドウ**（Ctrl+Shift+N、`file.new_window`）: 新しいプロセスで Linote を起動します（1 プロセスに 1 ウィンドウ）。

### 4.7 保存時の文字コード・改行（U1）

- ファイル > 保存時の文字コード（`file.save_encoding`）: UTF-8／UTF-8 (BOM 付き)／UTF-16 LE／UTF-16 BE／Shift_JIS (CP932)。UTF-16 は BOM 付きで保存します。本文は変えませんが、保存するまで**未保存の変更**として扱い、ステータスバーの表示はすぐ変わります。変換できない文字があれば、保存時に 4.3 の確認が出ます。
- ファイル > 保存時の改行（`file.save_eol`）: CRLF／LF／CR。**本文の改行をすべてその形式に変換**し（Undo できる）、以後の入力の改行も同じ形式になります。
- どちらも通常ファイル・無題・クリップボード由来の文書だけが対象です（メモは UTF-8 固定、巨大ファイルは読み取り専用）。
- 既知の制限: 変更後に Undo で保存時点へ戻ると、本文は戻るが保存時の文字コード・改行の指定は戻らず、文書は未変更と表示されます（保存し直すまで指定が残ります）。
- ファイル > フルパスをコピー（`file.copy_path`）、エクスプローラーで表示（`file.reveal_in_explorer`。ファイルを選択した状態で開く）は、ファイルのある文書で使えます。

### 4.7.1 保存時の整形（V5）

- 設定 `save`（15 章）で、**保存の直前**に本文を整形できます（どちらも既定は無効）。上書き保存・名前を付けて保存・すべて保存のどれでも行います。メモと巨大ファイルは対象外です。
  - `trim_trailing_whitespace`: 行末のスペースとタブを除きます（全角空白は除きません）。**言語が Markdown の文書では行いません**（行末 2 つの空白が改行の意味を持つため。表示 > 言語で Markdown にした文書も同じ）。
  - `ensure_final_newline`: 最終行の改行がなければ補います（文書の改行形式。CRLF／LF／CR）。本文が空（行末の空白を除いて空になる場合を含む）なら補いません。
- 整形は編集欄の上で行い、**1 回の Undo で整形前に戻せます**。カーソル・選択と先頭の表示行は保ちます（行末の空白の除去は Scintilla が位置を追従させ、末尾に改行を補うときは末尾にあったカーソルを元の文字の後ろに戻します）。変化がなければ何もせず、版も未保存の印も動かしません。保存を取り消したとき（確認ダイアログ、外部変更の案内など）は整形しません。保存に失敗しても整形は残ります（Undo できます）。
- 計算は GUI 非依存の純粋関数（`src/text/tidy.rs`。編集 > 変換 > 行末の空白を削除と共用）。

### 4.8 タブの操作（U4）

- **並べ替え**: タブを左右にドラッグすると、動かしている間に並びが入れ替わります（移動量が 5 px（96 DPI）以下の動きはクリック扱い）。入れ替わりは、ほかのタブの中心を越えた数で決めるので、幅の違うタブでも行き来しません。ドラッグしたタブがアクティブになり、未保存の丸などの状態は文書に付いてきます。タブがあふれて一部が見えないときは、カーソルの下のタブの位置へ動かします。ドラッグの途中でマウスを捕まえ直されたとき（Alt+Tab など）は、その時点の並びで終わります。
- **新しいウィンドウへ移す**: タブをウィンドウ全体（タイトルバー・枠を含む）の外へドラッグして離すか、タブの右クリックメニューの「新しいウィンドウに移動」（`file.move_to_new_window`）を選ぶと、その文書を**新しいプロセスのウィンドウ**で開き、**新しい側が取り込んだと確認できてから**元のタブを閉じます。離した位置に新しいウィンドウを置きます（左へウィンドウ幅の 1/4、上へ 20 px（96 DPI）ずらし、離した位置のモニターの作業領域に収めます。右クリックメニューからのときは既定の位置）。タブが 1 つだけのときは移せません（状態表示に出ます）。
  - 保存済みのファイル（巨大ファイルを含む）はパスを渡し、新しい側が自分で読みます。メモは先に保存領域へ書き出してから同じメモを渡し、新しい側が読みます（メモの版の照合は通常どおり）。
  - 未保存の変更があるファイル、無題、クリップボード由来の文書は、本文・文字コード・BOM・改行・元のパス・元のファイルの印・未保存の状態を受け渡しファイルに書いて渡します。新しい側は**未保存の文書として**開き（Undo の履歴は引き継がない）、すぐ復元データを書きます。元のファイルが移している間に変わっていれば、「上書きせず別に保存」の警告を出します。読み込みで不正なバイトを置き換えた文書、保存中の文書は移せません（理由を状態表示に出します）。
  - **確認の方法**: 送り側が `%LOCALAPPDATA%\Linote\handoff\` に受け渡しファイルを書いて `linote.exe --adopt <ファイル> [--pos x,y]` を起動し、0.1 秒ごとにファイルの有無を見ます（画面は止まりません）。新しい側は文書を開いてから、ファイルを改名して消す（`claim`）ことで取り込みを宣言します。ファイルが消えたら元のタブを閉じます（元の復元データも破棄）。最長 15 秒待ち、時間切れ・新しい側の終了・起動の失敗では、ファイルを取り消し（`cancel`）て**元のタブを残し**、ダイアログで知らせます。取り消しと取り込みの競合は、改名が原子的なので片方だけが勝ちます（取り消しに負けたら受け取り済みとして閉じ、取り込みに負けた新しい側は開いた文書を捨てます）。待っている間に元の文書を編集した場合も、元のタブは閉じず、知らせます。壊れた・古い（10 分超）・未対応の版・存在しない対象の受け渡しファイルは、新しい側が何も開かず、ファイルにも触れず、起動時にダイアログで知らせます（送り側は時間切れで元のタブを残します）。
- **右クリックメニュー**（タブ上）: 閉じる（`file.close`）／ほかのタブを閉じる（`file.close_others`）／右側のタブを閉じる（`file.close_right`）／新しいウィンドウに移動（`file.move_to_new_window`）／フルパスをコピー（`file.copy_path`）／エクスプローラーで表示（`file.reveal_in_explorer`）。右クリックしたタブがアクティブになり、そのタブを対象に実行します。使えない項目は灰色です（タブが 1 つだけなら「ほかのタブを閉じる」「新しいウィンドウに移動」、一番右なら「右側のタブを閉じる」、ファイルでなければパス関連）。「右側のタブを閉じる」は 4 章の「まとめて閉じる」と同じ確認で、取り消すとそこで止まります。
- 起動引数: `--adopt <ファイル>`（受け渡しファイルを受け取る。ファイルの引数は併用できる）、`--pos x,y`（ウィンドウの置き場所の目安。画面座標で負の値も可）。通常の利用では送り側が渡すもので、手で使う想定ではありません。

### 4.9 印刷（U5）

- **印刷**（ファイルメニュー、`file.print`、`Ctrl+P`）: Windows の印刷ダイアログ（プリンター、部数、ページ範囲、選択範囲のみ）を開いて、アクティブな文書を印刷します。選択範囲があれば「選択した部分」を選べます。本文は Scintilla の `SCI_FORMATRANGEFULL` でプリンターの DC に描きます。ページの区切りは、描かずに先に計算します（ページ範囲の指定と、フッターの「n / m」に使います）。印刷は UI スレッドで同期的に行うため、長い文書では印刷データを作る間、画面が応答しません。
- **ページ設定**（ファイルメニュー、`file.page_setup`）: 用紙、向き、余白（Windows のページ設定ダイアログ）。余白（0.01 mm 単位）、用紙の種類、向きは `settings.json` の `print` に保存され、次回の印刷とページ設定の初期値になります（用紙・向きは既定のプリンターの `DEVMODE` に反映します。プリンターの選択そのものは保存しません）。
- **ヘッダーとフッター**: ヘッダーは左にファイル名またはタブ名、右に印刷日時（`2026/11/14 09:05`）、フッターは中央にページ番号「n / m」（m は印刷する範囲の全ページ数、ページ範囲を指定しても n は全体の通し番号）。それぞれ罫線で本文と区切ります。ヘッダー・フッターの帯の分だけ本文の領域は狭くなります。
- **印刷の選択肢**（ファイルメニュー > 印刷の設定。`print.toggle_color`／`print.toggle_line_numbers`／`print.toggle_header`／`print.toggle_footer`）: 色分けして印刷する（`SC_PRINT_COLOURONWHITE`、オフなら白黒 `SC_PRINT_BLACKONWHITE`。背景は常に白）、行番号を印刷する、ヘッダー、フッター。メニューにチェックが付き、設定に保存されます。折り返しは、表示の設定に関わらず常に紙の幅で行います（`SCI_SETPRINTWRAPMODE`）。文字サイズは設定の文字サイズどおりで、画面の拡大率は反映しません。
- **対象外**: 印刷プレビュー。巨大ファイル（読み取り専用）は印刷できません（メニューは灰色、`Ctrl+P` では「巨大ファイル（読み取り専用）は印刷できません。…」と状態欄に出ます。`Capability::Print` を持たないため）。PDF にするには Windows の「Microsoft Print to PDF」を選びます。
- プリンターが 1 台もなければ「印刷 を使えません: 使えるプリンターがありません…」と表示します。余白が大きすぎて本文の領域がなければ、ページ設定で小さくするよう案内して印刷しません。
- 要件定義は `docs/tasks/U.md` の U5。印刷結果そのものは Windows 実機で確認します（`docs/verification/U.md`）。

## 5. タブを閉じる・終了時の確認

| 文書 | 変更あり（未保存）で閉じたとき |
|---|---|
| 通常／新規／クリップボード由来 | 「保存」「保存しない」「取り消し」を尋ねる。保存先のない文書は「名前を付けて保存」になる。保存に失敗・取り消しなら閉じない。「保存しない」では復元データも破棄 |
| メモ | **尋ねずに**メモとして保存してから閉じる。保存に失敗したら閉じない |
| 巨大（読み取り専用） | 尋ねずに閉じる |
| 変更なし | そのまま閉じる |

`Ctrl+W`（コマンド `file.close`）は引数 `force` を与えると確認せずに閉じます（メニューからは使えません）。

**すべて保存**（V2、`file.save_all`、`Ctrl+Alt+S`。グローバルキーは `Ctrl+Alt+V` のみで衝突しない）: 変更のある文書を左から順に保存します。ファイルのある文書は上書き保存（非同期）、メモはメモとして保存、名前のない文書は保存ダイアログを出し、取り消すとそこで止まり以降は保存しません。巨大ファイルは対象外。保存の途中で外部変更の案内などが出た文書はその案内に従います。文書 0 件では何もしません（メニューはグレー）。

**閉じたタブを開き直す**（V2、`file.reopen_closed`、`Ctrl+Shift+T`）: 閉じたファイル（巨大ファイルを含む）のパスとカーソル位置・先頭行、閉じたメモの ID を最大 20 件、その起動の間だけ覚えます（同じファイル・メモは新しい記録だけ残る。無題・クリップボード由来、別ウィンドウへの移動、開き直しによる置き換えは覚えない）。新しいものから開き、ファイルが存在しなければ飛ばして次へ、メモは ID で開きます（削除済みなら飛ばす）。すでに開いているファイルはそのタブに切り替わります。記録がなければメニューはグレー、コマンドは「開き直せる閉じたタブがありません」と表示します。文書 0 件でも使えます。

**まとめて閉じる**（U1）: 「ほかのタブをすべて閉じる」（`file.close_others`、アクティブな文書を残す）と「すべて閉じる」（`file.close_all`、閉じたあとは文書 0 件になる。1.1）は、文書を左から順に、上の表のとおり確認しながら閉じます。「取り消し」または「保存」（保存の完了を待つため閉じない）を選んだ文書でそこで止まり、以降は閉じません。

最後のタブを閉じたときも文書 0 件になります（無題は作りません。1.1）。

**終了時**: 文書を並び順に調べ、確認が必要な文書ごとに尋ねます。「保存しない」と答えた文書は、その後に編集されない限り再度は尋ねません。途中で「取り消し」にすると終了しません。メモは尋ねずに保存します。

## 6. 未保存変更の復元

- 対象は通常ファイル、新規未保存、クリップボード由来の文書です。メモと巨大ファイルは対象外です。
- 編集があると、最後の編集から **2 秒**で復元データを書き出します。入力が続いても、最初の未書き出しの編集から **30 秒**で書きます。書き出しはバックグラウンドで、古い版が新しい版を上書きしないよう版を照合します。
- 復元データには本文（UTF-8）、元のパス、文字コード・BOM・改行形式、開いたときのファイルの控え、版を含みます。初めて書くときに `recovery\` を作ります（起動経路では何も作りません）。
- 保存の成功、または「保存しない」による破棄で復元データを削除します。
- 起動後にバックグラウンドで `recovery\` を調べ、持ち主のいない復元データ（前回の異常終了など）があれば、最大 8 件を一覧して**「復元する／破棄する／あとで」**を尋ねます。
  - 復元: 未保存の文書として開きます。元ファイルには触れず、利用者が保存したときだけ書きます。元ファイルが復元データを作った後に変更されていた場合は、上書き保存を止め、別名保存を勧める警告を出します。
  - 破棄: 復元データを削除します。
  - あとで: そのまま残し、次の起動で再び尋ねます。
- 壊れた復元データや未知の版のデータは、読み込まず `recovery\quarantine\` へ移して件数を通知します（削除はしません）。
- 別のウィンドウ・プロセスが所有している復元データは、ロックファイルにより復元・削除しません。

## 7. 一時メモ

- **メモの一覧**（`Ctrl+Shift+M`）で小窓を開閉します。一覧は**初めて開くときに読み込みます**。検索欄に入力すると名前と本文を検索し、↑↓で選択、Enter またはダブルクリックでタブに開きます。Esc で閉じます。一覧は名前（本文に当たったときは抜粋）を左に、更新日時（今日は時刻、今年は月日、それ以前は年月日）を右に表示します。メモが 0 件、または検索に一致しないときは一覧の代わりに案内を出します。小窓の右下の「新規メモ」ボタンでメモを作成できます（左下の「削除」とは離して配置）。小窓の「削除」ボタン、または一覧で Delete キー（検索欄では文字の削除なので効きません）で、選択中のメモを削除できます（V2）。確認ダイアログを出し、保存領域の版を付けて消します（`MemoStore::delete`）。そのメモを開いているタブがあれば閉じ（未保存の編集は破棄）、一覧を読み直します。別の場所で変更されていて版が合わないときは、通知して削除しません。
- **検索の規則**: 大文字小文字を区別せず、全角英数・記号を半角に、ひらがなをカタカナにそろえて比べます。検索語は空白区切りの AND で、各語が名前か本文のどちらかにあれば一致です。名前に一致したものを先に、同じなら更新の新しい順に並べます。語が空なら全件（更新の新しい順）です。
- **名前の変更**: メモ > メモの名前を変更…。
- **自動保存**: 最後の編集から **1.5 秒**、入力が続いても **10 秒**で保存します。閉じるときと終了時にも保存します。メモ 1 件の本文は最大 64 MiB です。
- **保存形式**: UTF-8 の JSON（`format, id, name, created_ms, updated_ms, version, body`）。原子的に置換します。
- **同時アクセス**: メモごとに版を持ち、更新は前提の版を照合します。別のウィンドウなどで更新されていて版が食い違った場合、相手を上書きせず、自分の内容を「`<名前>（競合）`」という別のメモとして保存し、タブはそのメモに切り替わります（状態欄に通知）。
- メモの「名前を付けて保存」はファイルへの書き出しで、メモ自体は残ります（「書き出しました」と表示）。

## 8. クリップボード展開（グローバルショートカット）

- 既定のキーは **Ctrl+Alt+V**。アプリが起動していれば、他のアプリにフォーカスがあっても働きます（`RegisterHotKey`）。押すとウィンドウを前面に出し、クリップボードのテキスト（`CF_UNICODETEXT`）を未保存の新しいタブ「クリップボード N」に開きます。日本語・タブ・改行をそのまま保ち、新しい改行の形式は取り込んだテキストで最も多いものにします。
- エディタ内でも同じキーで同じコマンド（`clipboard.new_tab`）が動きます。専用のアプリ内キーはなく、通常の `Ctrl+V` は貼り付けです。
- テキストがなければ「クリップボードにテキストがありません」、他のアプリが使用中なら「クリップボードを開けません」と状態欄に出します。
- 前面に出せなかったときは「タスクバーから切り替えてください」と案内します。
- キーは `settings.json` の `keys."clipboard.new_tab"` で変更します（空文字で解除）。他のアプリと競合して登録できないときは、状態欄に「他のアプリが使用中のため登録できません。設定で変更してください」と出ます。表記が不正な場合も同様に通知します。変更は、設定画面の「キー」ページ（15.1）または `settings.json` の編集のあと「設定を再読み込み」で、**再起動せずに**登録し直します。設定画面で割り当てるときは、修飾キー（Ctrl／Alt／Shift／Win）が要ります（修飾キーなしは断ります）（登録できなかったときは同じ文を状態欄に出します）。
- 取り込んだタブは編集・検索・保存・未保存復元に対応します。

## 9. 検索・置換・Grep

検索・置換・Grep は 1 枚の小窓（`Ctrl+F`／`Ctrl+H`／`Ctrl+Shift+F` で開く）にまとまっています。選択文字列があれば検索欄に入ります。

- 上部の「検索｜置換｜Grep」で用途を切り替えます（キーで開いたときはその用途）。用途に関係する欄とボタンだけを表示し、窓の高さも合わせます（Grep では結果の一覧の分を広げ、高さを覚えます）。
- 各欄は左に名前（検索する文字列、置換後の文字列、フォルダー、対象の拡張子、除外フォルダー）、空の欄には薄い字で入力例を出します。オプション（大文字小文字を区別、単語単位、正規表現）は欄の位置に揃えて横に並べます。
- ボタンは右下にまとめ、既定のボタン（Enter）を用途ごとに 1 つにします: 検索は「次を検索」「前を検索」、置換は「置換」「すべて置換」「次を検索」、Grep は「検索開始」「中止」（中止は実行中だけ押せる）。検索欄で Enter は、Grep の用途では Grep を始めます。
- 状態文は、文があるときだけ場所を取ります。3 行を超える長い文のときだけスクロールバーを出します。

### 9.1 文書内の検索・置換

- オプション: 「大文字小文字を区別」「単語単位」「正規表現」「選択範囲内」。ボタン: 次へ／前へ／置換／すべて置換／Grep／中止。
- 検索欄で Enter＝次、Shift+Enter＝前。置換欄で Enter＝置換。
- **F3／Shift+F3**（検索欄が閉じていても）: 直前の検索条件（検索欄に条件があればそれ）で次／前へ（端で折り返し）。条件がなければ、選択中の文字列（1 行・256 バイトまで）、それもなければカーソル位置の単語を検索語にして始めます（検索欄にも入ります）。選択もカーソル位置の単語もなければ小窓を開きます。巨大ファイルでも同様です（選択文字列のみ。単語は使いません）。
- **Ctrl+F3**（選択文字列を次へ検索）: 選択中の文字列（なければカーソル位置の単語）を検索語にして次の一致へ移ります。検索欄の条件も更新します（検索欄が正規表現のときは記号をそのまま探すよう退避します）。
- **全一致の強調**（U3）: 検索欄の入力・オプションの変更のたびに、アクティブな文書のすべての一致を Scintilla のインジケーター（琥珀色の半透明の枠）で強調し、現在の一致（選択と同じ範囲）は橙色で別に示します。F3 などで一致へ移ったときにも付きます。検索欄の状態欄（閉じているときは画面下の状態表示）に「**n / 全 m 件**」（現在の一致が一致のどれでもなければ「全 m 件」、0 件は「見つかりません」）を出します。強調は最大 **20000 件**で、超えたら「全 20000+ 件」のように表示します（一致の移動は上限と無関係）。1 MiB 以上の文書はワーカーで検索し、文書の版と世代を照合してから反映します。強調は検索欄を閉じても残り、**Esc（本文にフォーカスがあるとき）、文書の編集、別のタブへの切り替え、検索語が空・無効**になると消えます。巨大ファイルでは強調しません。
- **選択範囲内**（V3）: 「選択範囲内」にチェックすると、**チェックした時点の選択範囲**が検索の対象範囲になり、本文に薄い青の枠（Scintilla のインジケーター）で示されます。次へ・前へ（端では範囲の反対側へ折り返す）、全一致の強調と「n / 全 m 件」、置換、すべて置換が、すべてこの範囲の中に限られます。範囲の外にある選択から始めたときは、範囲の端から探します。「置換」は、選択が範囲内の一致のときだけ置換し、範囲外なら置換せず範囲内の次の一致へ移ります。「すべて置換」は Undo 1 回で戻り、置換後の範囲を選択したままにします。範囲は文書内のインジケーターが持つので、範囲の前後を編集しても範囲は追従します（範囲の本文をすべて消すなどで範囲が失われたら、案内して何もしません）。範囲の本文だけを対象にするので、`^`・`\b` などは範囲の端を文書の端として扱います。大きな範囲はワーカーで処理します。選択がないときはチェックを入れられず（案内して外れたままにします）、巨大ファイルでも使えません。**別のタブへ切り替える、チェックを外す、文書を閉じる**と範囲は解除され、チェックも外れます。文書 0 件でも安全に動きます（チェックは入りません）。
- **履歴**（V3）: 検索欄・置換欄・Grep の起点欄はドロップダウン付きの入力欄で、実行した語を新しい順に最大 **20 件**ずつ一覧から選べます（重複は先頭へ移す。空の語は残さない）。検索欄は次へ・前へ・置換・すべて置換・Grep の実行時、置換欄は置換・すべて置換の実行時、起点欄は Grep の実行時に記録し、`settings.json` の `search_history`（`find`／`replace`／`grep_dir`）に保存します。一覧から選ぶと入力欄に入ります。F3 や Ctrl+F3 だけで実行した語は記録しません。設定ファイルが壊れているときは、その起動の間だけ保ち、ファイルには書きません。
- 正規表現は Rust `regex` の構文です。後方参照・先読み・後読みは使えません。パターンが空、4096 バイト超、無効な場合は、検索欄の近くにエラーを表示します。長さ 0 の一致は無視します。
- 「すべて置換」は Undo 1 回で戻せます。長い文書の処理はバックグラウンドで行い、結果は文書 ID と版を照合してから反映します。
- 後ろ向きの検索は、窓の境界で 64 KiB を超える一致を見落とすことがあります。

### 9.2 Grep

- 起点フォルダー（既定はアクティブな文書のフォルダー）を指定し、「Grep」または起点欄で Enter。結果にファイル名・行番号・該当行を逐次表示し、選択（Enter／ダブルクリック）でそのファイルを開いて該当行へ移ります。「中止」で止められます。
- 検索は行単位です。文字コードは UTF-8／UTF-16／CP932（通常編集と同じ判定）。
- 除外: バイナリ（先頭 8 KiB に NUL を含む非 UTF-16 のファイル）、**16 MiB** を超えるファイル、既定では隠しフォルダー・隠しファイル（`.` で始まる名前、または Windows の隠し属性）、`.git`／`.hg`／`.svn`／`node_modules`／`target` フォルダー。シンボリックリンクはたどりません。
- 結果は最大 **2000 件**で打ち切ります（打ち切りの通知の表示は未確認）。1 件の行の抜粋は最大 240 バイトです。
- 小窓の「対象の拡張子」は `*.rs;*.txt`／`rs txt`／`.rs txt` を受け付けます。空欄・`*`・`*.*` は全対象で、大文字小文字を区別しません。「除外フォルダー」は `;` 区切りのフォルダー名（既定は `.git;.hg;.svn;node_modules;target`）です。「隠しファイルも対象」で隠しファイル・フォルダーを含められます（除外フォルダーの指定は引き続き有効）。条件は Grep 実行時に設定の `grep` へ保存します。

### 9.3 巨大ファイルでの検索

F3／Shift+F3 も使えます（強調はなし）。検索は使えます（正規表現は**行単位**）。置換は使えず、「巨大ファイルは読み取り専用のため、置換は使えません（正規表現の検索は行単位です）」と案内します。

## 10. 巨大ファイル

### 切り替え条件（暫定値）

| 条件 | しきい値 | 判定のタイミング |
|---|---|---|
| ファイルの容量 | **256 MiB** を超える | 開く前（容量だけで判定） |
| 行数 | **1000 万行**を超える | 読み込み後 |
| 最も長い行 | **8 MiB**（バイト）を超える | 読み込み後 |

行数・最大行長の判定は、文字コードが UTF-8 で、本文が 8 MiB を超えるときだけ行います。巨大モードは **UTF-8（ASCII 互換）のファイルだけ**開けます。UTF-8 らしくない巨大ファイルは「通常編集で開ける大きさにしてから…」というエラーになり、開けません。巨大ファイルを「文字コードを指定して開き直す」ことはできません。

### できること

- 読み取り専用のタブで開きます（ステータスバーに「読み取り専用」を表示）。本文は読み込まず、表示範囲だけをディスクから読みます。先頭の表示は索引の完成を待たず、行索引は裏で作り、進み具合をステータスバーに出します。
- スクロール、先頭・末尾への移動（Home／End、Ctrl との組み合わせ）、行へ移動（`Ctrl+G`）、範囲選択とコピー（上限 64 MiB）、検索（第 9.3 節）。
- 折り返しと構文着色はありません（表示の設定の折り返し・書体・拡大・空白の表示などは巨大ファイルのビューには適用しません）。**行番号の表示・非表示だけは、通常編集と同じ設定（表示 > 行番号を表示）が巨大ファイルのビューにも適用されます**（隠すと行番号の欄がなくなり、本文が左へ寄ります。隠したまま開いたビューも隠れます）。桁の割り当ては等幅（全角は 2 桁、タブは 4 桁）で、長い行は 4 KiB ごとの表示行に分けます。
- 描画は Direct2D／DirectWrite。使えない環境（Wine など）では GDI に切り替えます。
- メモリ使用量はファイルの大きさに依存しない上限があります（ブロックキャッシュ 32 MiB、行索引 4 MiB など）。
- **外部変更**: 元ファイルの切り詰め・置換・追記を長さと更新時刻の比較で検知すると、そのビューは無効になり、索引と検索結果を捨てて利用者に知らせます。
- 編集、保存、Undo、Markdown プレビューはできません。

## 11. Markdown プレビュー

- **開き方**: 表示 > Markdown プレビュー（右ペイン）`Ctrl+Shift+P`、または（別ウィンドウ）。開いていれば閉じます。対象は拡張子 `.md`／`.markdown` の文書だけです。それ以外では「Markdown の文書（拡張子 .md または .markdown）でだけプレビューできます」と表示します。プレビューは最後にアクティブになった Markdown 文書に追従します。右ペインと別ウィンドウは**どちらか一方**です（0.1.5）。一方を開いているときにもう一方を選ぶと切り替わり、表示中の内容をそのまま引き継ぎます（アクティブなタブが Markdown でなくても、表示中の文書で切り替えられます）。
- **遅延初期化**: プレビューを初めて開くまで、WebView2 に関する処理（ランタイムの確認を含む）は一切行いません。WebView2 ランタイムがなければ案内（Evergreen 版のインストールを勧める文）を表示し、編集は続けられます。
- **変換**: 編集の約 250 ミリ秒後（本文が大きいほど長く、最大 1.5 秒）に、バックグラウンドで変換します。変換中に次の版が来れば中止し、古い結果は文書 ID と版を照合して捨てます。
- **対応する書式**: 見出し、段落、表、チェックリスト、取り消し線、脚注、コードブロックなど（`pulldown-cmark` の GFM 系）。数式・メタデータ・見出し属性・Wiki リンクは無効です。配色はテーマに連動します。
- **スクロール位置**: 同じ文書の更新では、表示を替える前のスクロール位置を保ちます（文書が短くなれば末尾に収まります）。別の文書に切り替えたときは先頭から表示します。位置の読み取りと復元はアプリ側から `ExecuteScript` で行い、文書のスクリプトは無効のままです（実行するのは固定の文字列と数値だけ）。
- **大きさの上限**: 本文が **16 MiB** を超える文書はプレビューせず、「この文書は大きすぎてプレビューできません」と表示します（編集は続けられます）。

### 安全性の制約

- 文書中の **生の HTML は文字として表示**します（エスケープ。ブロックは `<pre class="raw-html">`）。スクリプトやイベント属性は出力しません。
- **リンク**は `http`／`https`（権限部あり）、`mailto`、文書内の `#...` だけを許可します。`javascript:`、`data:`、`file:`、相対パス、`//host` などは、リンクにせず文字として表示します。
- **画像は読み込みません**。`<img>` は出力せず、代替テキストを表示し、`http`／`https` の画像ならその URL へのリンクにします。ローカル画像も表示しません。
- 出力する HTML には Content-Security-Policy を最初に付けます: `default-src 'none'; style-src 'unsafe-inline'; script-src 'none'; img-src 'none'; font-src 'none'; connect-src 'none'; media-src 'none'; object-src 'none'; frame-src 'none'; child-src 'none'; worker-src 'none'; manifest-src 'none'; form-action 'none'; base-uri 'none'`。
- **ナビゲーション**: こちらが読み込ませた文書と同じ文書内の `#` への移動以外は取り消します。リンクのクリック（利用者の操作）で `http`／`https`／`mailto` のときだけ、既定のブラウザー（メールソフト）に渡します。URL が 2048 文字を超える、または制御文字・空白・`"` を含む場合は渡しません。

## 12. 構文着色の対象言語

拡張子（大文字小文字を区別しない）で決めます。新規・メモ・クリップボード由来の文書は着色しません。16 MiB を超える文書は着色しません。

| 言語 | 拡張子 | 字句解析器 |
|---|---|---|
| C | c, h | cpp |
| C++ | cpp, cc, cxx, c++, hpp, hh, hxx, h++, inl, ipp | cpp |
| Java | java | cpp（Java のキーワード） |
| Rust | rs | rust |
| Markdown | md, markdown, mkd, mdown | markdown |
| JSON | json, jsonc, json5 | json |
| YAML | yaml, yml | yaml |
| INI | ini, cfg, conf, properties, inf, reg, editorconfig | props |
| TOML | toml | props（代用。専用の解析器は未収録） |
| HTML | html, htm, xhtml | hypertext |
| XML | xml, xsd, xsl, xslt, svg, xaml, csproj, vcxproj, props, targets, plist, config, manifest, resx | xml |
| Python | py, pyw, pyi | python |
| PowerShell | ps1, psm1, psd1 | powershell |
| バッチ | bat, cmd | batch |
| SQL | sql | sql |
| ログ | log | errorlist（簡易表示） |

上記以外の拡張子はプレーンテキストです。ステータスバーに言語名を表示します。

**言語の手動選択**（V2、表示 > 言語、`view.language`）: アクティブな文書の言語を、上の一覧の言語・「なし（プレーンテキスト）」・「拡張子から自動」から選べます（メニューには現在の選択に印が付き、手動の指定がなければ「拡張子から自動」に付く）。文書ごとの設定で、保存しません（再起動・開き直しでは拡張子から決まる）。名前を付けて保存しても手動の選択は保たれ、「拡張子から自動」で拡張子からの判定に戻ります。ステータスバーの言語名に反映されます。巨大ファイル（読み取り専用の別ビュー）は対象外で、16 MB を超える本文は着色しません。

## 13. テーマ・DPI

- 設定 `theme` は `system`（既定。Windows の明暗に連動）／`light`／`dark`。メニュー「表示 > テーマを切り替え」で システム → ライト → ダーク の順に切り替え、設定に保存します（設定ファイルが壊れている間は保存しません）。
- 本文・タブ・ステータスバー・小窓・プレビューに同じ配色を適用します。構文着色は意味の分類ごとに色を決めています。
- DPI 変更（モニター間の移動を含む）で、レイアウト・書体・行番号欄を更新します。

### 13.1 表示の設定（U2）

表示メニューで変える設定は、すべて `settings.json` の `view`（第 15 章）に保存し、**全タブに同時に適用**します（文書ごとの設定はありません）。変更は即座に反映し、次の起動でも引き継ぎます。設定ファイルが壊れている間は、変更はその起動の間だけ有効で、保存しません。

- **折り返し**（表示 > 折り返し）:
  - 折り返さない（既定）／ウィンドウ幅で折り返す（単語単位）／ウィンドウ幅で折り返す（文字単位）／指定した桁で折り返す...。
  - 折り返した行は元の行と同じ深さのインデントで表示します（Scintilla の `SC_WRAPINDENT_SAME`）。
  - **指定した桁**: 入力欄で桁数（10〜500、既定 80）を指定します。本文の領域の幅を「桁数 × 半角 1 文字（`0`）の幅」に合わせるため、編集欄の右余白を計算して設定し、ウィンドウの大きさ・書体・拡大・行番号欄の幅が変わるたびに計算し直します（ウィンドウが桁数分より狭いときはウィンドウ幅で折り返します）。折り返しの方法は単語単位です。全角文字は半角 2 文字分の幅なので、全角だけの行は桁数の半分の文字数で折り返されます。比例フォントでは「桁」は `0` の幅を基準にした目安です。
  - **ガイド線**: 桁指定のときだけ、その桁に縦線を出します（表示 > 折り返し > 折り返し桁のガイド線で切り替え。既定はオン）。
  - 取り消し・範囲外・数字でない入力では何も変えず、状態表示に理由を出します。
  - 巨大ファイルのビューは対象外です。
- **書体と文字サイズ**（表示 > フォント...）: Windows の標準のフォント選択ダイアログで書体とサイズ（6〜72 pt）を選びます。既定に戻すには「既定のフォントに戻す」（書体は既定の候補、11 pt）。
- **拡大・縮小**: Ctrl+マウスホイール、Ctrl+Plus（Ctrl+;＝日本語配列、英語配列では Ctrl+Shift+= でも可）、Ctrl+Minus、テンキーの Ctrl+＋／−、Ctrl+0 で元に戻す。1 段階は文字サイズに 1 pt を足し引きする（−10〜+20）。拡大率は文字サイズに対する割合として状態表示に出し、設定に保存します。巨大ファイルのビューには適用しません。
- **空白・タブの表示**、**改行記号の表示**、**行番号の表示**（既定はオフ・オフ・オン）、**現在行の強調**、**対応する括弧の強調**（既定はオン）。括弧の強調は `()[]{}` のカーソルの前後 1 文字を調べ、対応があれば強調し、対応がなければ別の強調にします。2 MB を超える文書では探索が重いので行いません。
- **タブ幅**（表示 > タブ幅: 2／4／8、既定 4）と **タブをスペースで入力**（既定はオフ。Tab キーでタブ文字の代わりに、タブ幅ぶんの位置までスペースを入力する）。すでにある文書の本文は変えません。
- **自動インデント**（既定はオン）: Enter で改行したとき、直前の行の行頭の空白（スペースとタブ）をそのまま引き継ぎます。貼り付けや読み取り専用の文書では働きません。
- 切り替え項目とタブ幅・折り返しの現在の選択は、メニューの印（チェック）で示します。
- いずれも引数で指定して実行できます（第 14 章。切り替えは `enabled` を省くと反転）。

### メニュー・タブ・フォントの調整（0.1.1）

- ダークテーマではメニューバー（項目のない右側も含む）、ドロップダウン、タブの右クリックメニューを共通の背景・文字色で描画します。無効項目・選択・チェック・アクセスキーを保ち、ライトテーマへ戻すと標準メニュー描画へ戻ります。設定画面と標準フォント選択ダイアログは Windows の標準の見た目です。
- タブ幅は実際の UI フォントでファイル名を測って決めます（自然幅72〜220 DIP）。幅不足時は短い名前の幅を保って長い名前から縮め、長い文字列は末尾を省略します。最小幅でも全件が収まらない場合は選択タブを含む範囲を表示し、Ctrl+Tab等で選ぶと表示範囲が追従します。極端に狭い幅では閉じる印を隠して、隣のタブへの操作領域のはみ出しを防ぎます。
- タブの高さは OS の UI フォントの実測文字高に上下各4 DIPを加え、最小24 DIPとします（従来32 DIP）。起動時とDPI変更時にOSのUIフォントから再計算し、大きな文字でも切れないようにします。本文フォントの設定は本文に適用し、タブ等はOSのUIフォントを使います。
- 本文フォントは「表示 > フォント...」、または「設定 > 表示 > 本文フォント > フォントを選択...」でインストール済みの書体から選択できます。現在のフォント名・ptを表示し、標準選択ダイアログの初期サイズはモニターDPIに合わせます。設定画面でフォントを選択・既定へ戻しても、ほかの未適用の変更は維持します。

### 設定画面の配置（0.1.7）

各ページは「欄の名前｜値」の 2 列で、名前の列幅はそのページでいちばん長い名前に合わせ、値（選択肢・数値）の左端を揃えます。選択肢は内容に合う幅で、ページの右端まで伸ばしません。ボタンは文字に合わせた幅（最小 88 DIP）です。本文フォントは名前の列に「本文フォント」、値の列に書体名と pt、その下に「フォントを選択...」「既定に戻す」を並べます。キーのページは、1 行目に「新しいキー［入力欄］［割り当て］」、2 行目に「割り当てを外す」「既定に戻す」、右端に離して「すべて既定に戻す」を置き、一覧の最後の列は右端まで広げます。

### 設定画面の文字切れ対策とステータスバー（0.1.2）

設定画面はUIフォントでラベル・説明文の折り返し高さを測り、項目ごとの行高を確保します。フォント名と選択ボタンを別の行に配置し、キーの説明文も必要な高さを取ります。画面の作業領域を超えるページは縦スクロールでき、Tabで移った項目も表示範囲へ追従します。キー一覧の列幅は内容と見出しに合わせ、長い列は横スクロールとラベルのヒントで確認できます。

同じ対策を検索小窓の状態文・入力ダイアログの案内文へ適用しています。長い検索エラーは複数行で表示し、必要なら縦スクロールで全文を読めます。検索・メモ小窓の最小寸法と部品の高さもUIフォントから計算します。

表示 > ステータスバーを表示（`view.status_bar`）と設定 > 表示からステータスバーを切り替えられます。設定 `view.status_bar` は真偽値、既定 `true` で、不正な値も `true` として読みます。非表示時は本文・ペインを下端まで広げ、表示内容の状態は保持します。設定の保存・再読み込みと文書0件の状態でも操作できます。

### 行の整理とブックマーク（V6）

- 昇順・降順の並べ替えと重複行の削除は、選択に触れる行全体を対象にします。選択の終端が行頭ならその行は含めず、選択がなければ全文、矩形・複数選択なら最初から最後の行までを対象にします。Unicode コードポイント順で大文字小文字を区別して安定に並べ替え、重複除去は最初の出現を残します。末尾改行の有無と各位置の改行形式は保持します。
- 変更は 1 回の Undo で戻せ、同じ結果なら本文・版・Undo 履歴に触れません。大きな本文の整理はワーカーで計算し、結果の反映前に文書 ID と版を照合します。巨大文書・読み取り専用では整理できません。
- ブックマークは文書ごとに Scintilla のマーカーとして保持し、保存しません。行番号とは別の小さな余白にテーマに合う印を表示します。次・前への移動は端で折り返し、折りたたまれた行も表示します。印がなければ状態欄で知らせます。巨大文書では無効です。

## 15. 設定ファイル `settings.json`

場所: `%LOCALAPPDATA%\Linote\settings.json`（UTF-8 の JSON）。ファイルがなければ既定値で動作し、**設定を変更して保存するときに初めて作ります**（「設定ファイルを開く」でも作ります）。起動時に読み、実行中は再読み込み（15.1）で読み直します。

```json
{
  "version": 1,
  "theme": "system",
  "keys": { "clipboard.new_tab": "Ctrl+Alt+V", "file.save": "" },
  "recent_files": ["C:\\work\\a.txt"],
  "restore_session": true,
  "new_file": { "encoding": "utf-8", "eol": "crlf" },
  "save": { "trim_trailing_whitespace": false, "ensure_final_newline": false },
  "window": { "x": 100, "y": 80, "width": 1100, "height": 720, "maximized": false },
  "search_history": { "find": ["foo"], "replace": [], "grep_dir": ["C:\\work"] },
  "view": { "wrap": "column", "wrap_column": 80, "font": "", "font_size": 11, "zoom": 0,
            "show_whitespace": false, "show_eol": false, "line_numbers": true,
            "highlight_current_line": true, "highlight_braces": true, "edge_guide": true,
            "tab_width": 4, "use_spaces": false, "auto_indent": true },
  "print": { "margin_left": 2000, "margin_top": 2000, "margin_right": 2000, "margin_bottom": 2000,
             "landscape": false, "paper_size": 0, "color": true, "line_numbers": false,
             "header": true, "footer": true },
  "mcp": { "enabled": false }
}
```

| キー | 型 | 既定 | 説明 |
|---|---|---|---|
| `version` | 整数（1 以上） | 1 | 形式の版。新しい版の値も保って書き戻します |
| `theme` | `"system"`／`"light"`／`"dark"` | `"system"` | 明暗テーマ |
| `keys` | オブジェクト（コマンド ID → キー表記） | なし | コマンドごとのキー。ないコマンドは既定値。**空文字 `""` は割り当てなし**。グローバルショートカット（`clipboard.new_tab`）も同じ表 |
| `recent_files` | 文字列の配列 | `[]` | 最近使ったファイル（新しい順、`recent_files_max` 件まで。大文字小文字を区別せず重複を除く）。起動時に存在確認はしない |
| `recent_files_max` | 整数（0〜30） | 10 | 最近使ったファイルの上限。0 では記録せず、件数を減らすと保存時に切り詰める。不正値は10として読む |
| `external_change` | `"notify"`／`"reload_if_clean"` | `"notify"` | 外部変更時の通知／未保存変更がない通常文書の自動読み直し（4.5）。不正値は通知として読む |
| `grep` | オブジェクト（`extensions`、`exclude_dirs`、`include_hidden`） | `""`、`".git;.hg;.svn;node_modules;target"`、`false` | Grep の絞り込み（9.2）。不正な項目は既定値として読み、知らない項目は保持する |
| `restore_session` | 真偽値 | `true` | 起動時に前回のタブを開き直す（1.1）。真偽値でなければ `true` として読む |
| `new_file` | オブジェクト（`encoding`、`eol`） | `{"utf-8", "crlf"}` | 新規文書の既定の形式（4.2）。`encoding` は `"utf-8"`／`"utf-8-bom"`／`"shift_jis"`（`"cp932"` も可）／`"utf-16le"`／`"utf-16be"`（UTF-16 は BOM 付き）、`eol` は `"crlf"`／`"lf"`（`"cr"` も読む）。不正な値は既定として読む |
| `save` | オブジェクト（`trim_trailing_whitespace`、`ensure_final_newline`） | 両方 `false` | 保存時の整形（4.7.1）。真偽値でなければ `false` として読む |
| `window` | オブジェクト（`x`、`y`、`width`、`height`、`maximized`） | なし | 前回のウィンドウの位置・大きさ（通常状態の矩形、画面座標）と最大化の有無（1.1）。終了時に書く。値が不正（幅・高さが 200 未満、数値でないなど）なら無視して既定の位置で開く |
| `search_history` | オブジェクト（`find`／`replace`／`grep_dir` は文字列の配列） | すべて `[]` | 検索欄・置換欄・Grep の起点欄の履歴（新しい順、各最大 20 件、重複なし。9.1）。実行のたびに更新して保存する（書き込むのはこの 3 項目だけで、知らない項目は残す）。値が不正（オブジェクトでない、文字列でない要素）なら読み飛ばして空として読む |
| `view` | オブジェクト | 下記の既定 | 表示の設定（13.1）。全タブに適用する。値が不正な項目は既定値（数値は範囲内）として読み、設定ファイル全体は壊れていないとみなす。`view` がオブジェクトでなければ壊れているとみなす |
| `view.wrap` | `"none"`／`"word"`／`"char"`／`"column"` | `"none"` | 折り返し（しない／単語単位／文字単位／指定した桁） |
| `view.wrap_column` | 整数（10〜500） | 80 | `wrap` が `column` のときの桁数 |
| `view.font` | 文字列 | `""` | 書体。空は既定（Cascadia Mono → Consolas → MS Gothic） |
| `view.font_size` | 整数（6〜72） | 11 | 文字サイズ（pt） |
| `view.zoom` | 整数（−10〜20） | 0 | 拡大・縮小（文字サイズに足す pt）。Ctrl+ホイールの変更も保存する |
| `view.show_whitespace`／`view.show_eol` | 真偽値 | `false` | 空白・タブ／改行記号の表示 |
| `view.status_bar` | 真偽値 | `true` | ステータスバーを表示。非表示時は本文の高さを広げる |
| `view.line_numbers` | 真偽値 | `true` | 行番号の表示（巨大ファイルのビューにも適用） |
| `view.highlight_current_line`／`view.highlight_braces` | 真偽値 | `true` | 現在行／対応する括弧の強調 |
| `view.edge_guide` | 真偽値 | `true` | 桁指定の折り返しのガイド線 |
| `view.tab_width` | 2／4／8 | 4 | タブ幅（それ以外の値は 4） |
| `view.use_spaces` | 真偽値 | `false` | Tab キーでスペースを入力 |
| `view.auto_indent` | 真偽値 | `true` | 自動インデント |
| `print` | オブジェクト | 下記の既定 | 印刷の設定（4.9）。値が不正な項目は既定値として読む。オブジェクトでなければ壊れているとみなす |
| `print.margin_left`／`margin_top`／`margin_right`／`margin_bottom` | 整数（0〜10000、0.01 mm） | 2000（20 mm） | 余白 |
| `print.landscape` | 真偽値 | `false` | 用紙の向きが横 |
| `print.paper_size` | 整数（Windows の `DMPAPER_*`。0 はプリンターの既定） | 0 | 用紙の種類 |
| `print.color`／`print.line_numbers`／`print.header`／`print.footer` | 真偽値 | `true`／`false`／`true`／`true` | 色分け、行番号、ヘッダー、フッター |
| `mcp.enabled` | 真偽値 | `false` | MCP 連携の有効化（現在は読むだけで、何も起動しません） |

- 知らない項目は読み込んだまま保持し、書き戻すときに失いません。
- 保存の直前にファイルを読み直し、変更する項目だけを差し替えて、原子的な書き込みで置換します。
- **壊れている場合**（JSON として読めない、型が違う、`theme` が不正、UTF-8 でないなど）: 既定値で起動し、「設定ファイルを読めません（理由）。既定の設定で動作します（ファイルは上書きしません）」と状態欄に出します。壊れている間は、設定の保存（テーマ切り替えの保存など）を行わず「設定ファイルが壊れているため、設定を保存しませんでした」と表示します。利用者が直すまで上書きしません。
- 設定画面（15.1）で、テーマ、前回のタブの復元、新規文書の既定、保存時の整形、外部変更時の動作、最近使ったファイルの件数、表示の設定（`view`）、キー割り当て（`keys`）を変えられます（拡大率は対象外）。テーマと表示の設定は表示メニューからも変えられ、保存します。印刷の設定は印刷の設定メニューとページ設定から、キー割り当ては設定画面の「キー」ページ（V4-2）で変えられます。それ以外は手で書き換えます。復元・メモの書き出し間隔など、ほかの項目は設定できません。

### 15.1 設定の再読み込みと設定画面（V4-1）

**再読み込み**（`app.reload_settings`、ファイル > 設定を再読み込み）は、`settings.json` を読み直して、実行中のウィンドウに反映する唯一の経路です。今の設定との違いがあった項目だけを反映します。

- テーマ（明暗の配色、タイトルバー、小窓、プレビュー）、`view` の全項目（折り返し・書体・拡大率・空白の表示・タブ幅など。全タブと編集欄）、`keys`（キー入力の解釈とメニューのキー表示を作り直す）、グローバルショートカット（`keys."clipboard.new_tab"` が変わったときだけ登録し直す。登録できなければ状態欄に出す）、検索・置換・Grep の履歴の欄（小窓が開いていれば）、最近使ったファイル（文書 0 件の案内を含む）。印刷の設定、`restore_session`、`window` は、使うとき（印刷・終了時）に設定を読むので、読み直した値に替わります。
- キーの設定に問題（表記の誤り・重複）があるときは、起動時と同じ「キーの設定に問題があります: …」を状態欄に出します（誤った割り当ては既定値で補います）。
- 読み直した結果は状態欄に「設定を再読み込みしました（変更: テーマ、表示、…）」または「（変更なし）」と出します。
- **自動で読み直す**: ウィンドウが前面に戻ったとき、設定ファイルの更新時刻と長さを前回読んだ（書いた）ときと比べ、変わっていれば読み直します（ほかのウィンドウや手での編集を拾う）。変更があったときだけ「設定ファイルの変更を反映しました（変更: …）」と知らせます。**自分が書いた直後には再読み込みしません**: 書き出し（ワーカー）が終わったときのファイルの印を覚え、書き出しが残っている間は検出を止め、読み直した内容が今の設定と同じなら何も反映しません。
- **Linote のタブで `settings.json` を保存したとき**も読み直します（保存の完了時）。
- **読めない（壊れている）とき**: 今の設定を保ち、「設定ファイルを読めません（理由）。今の設定のまま動作します（ファイルは上書きしません）」と状態欄に出します。以後の書き込みは止まります（第 15 章の規則どおり）。直して読めるようになると「設定ファイルを読めたので、保存を再開します」と出して書き込みを再開します。ファイルが消えたときは今の設定を保ち、設定を変えると作り直します。
- **設定ファイルを開く**（`app.open_settings_file`）: ファイルがなければ今の設定で作ってから、Linote のタブで開きます。設定ファイルは「最近使ったファイル」に載せません（載せると、開いた直後に設定ファイルを書き換えてしまうため）。

設定の保存は専用ロックファイルでプロセス間排他し、最新ファイルへ変更した項目だけを反映します。別ウィンドウの変更や未知の項目を保持し、保存待ち中の再読み込みは保存完了後に行います。

**設定画面**（`app.settings`、ファイル > 設定...、Ctrl+,）はモーダルのダイアログで、左にページの一覧、右にそのページの項目を出します（標準のダイアログの見た目。テーマの色には合わせません）。ボタンは OK／キャンセル／適用です。

- 数値の入力に誤りがあるときは、その項目のページへ戻り、入力欄を選択します。
- 一般: テーマ（システムに合わせる／ライト／ダーク）、起動時に前回のタブを開き直す、外部変更時の動作（通知／未保存の変更がなければ読み直す）、最近使ったファイルの件数（0〜30）。
- ファイル（V5）: 新規文書の文字コード・改行（`new_file`）、保存時に行末の空白を削除（Markdown を除く）、保存時に最終行の改行を補う（`save`）。
- 表示: 折り返し（折り返さない／ウィンドウ幅（単語単位・文字単位）／指定した桁）、折り返す桁（10〜500）、折り返し桁のガイド線、書体（「フォントを選択...」で標準のフォント選択ダイアログ、「既定に戻す」で既定の書体と 11 pt）、文字サイズ（6〜72 pt）、空白とタブ・改行記号・行番号の表示、現在行・対応する括弧の強調、タブ幅（2／4／8）、Tab キーでスペースを入力、自動インデント。拡大率は対象外（Ctrl+ホイールなどで変える）。
- 数値の欄が数字でない・範囲外のときは、OK・適用を止めてその欄に戻し、理由を出します。
- OK・適用は、まず最新の `settings.json` を読み直し（ほかのウィンドウの変更を失わないため）、**画面を開いた時点から変えた項目だけ**を差し替えて保存し、再読み込みと同じ経路で実行中のウィンドウに反映します（「設定を保存して反映しました」）。知らない項目は保たれます。キャンセルでは何も変えません。適用のあとも画面は開いたままで、続けて編集できます。
- 設定ファイルが壊れているときは、画面の上部に理由と「OK・適用は、この起動の間だけ反映します（保存しません）」を出し、そのとおりに動きます（「設定をこの起動の間だけ反映しました（設定ファイルが壊れているため保存していません）」）。保存場所を決められないときも同様です。
- ページと項目は表（`src/appdata/settings/items.rs`）で定義していて、ページや項目の追加は表への追記で済みます。
- **キー**（V4-2）: コマンドの一覧（ListView。列は 分類・コマンド・キー・既定との違い。分類、コマンド名の順）と、その上の絞り込みの欄（空白で区切った語がすべて、分類・コマンドの表示名・コマンド名・今のキーのどれかに含まれるものだけを出す。大文字小文字は区別しない）。グローバルショートカット（`clipboard.new_tab`）も一覧に含み、名前の後ろに「（グローバル）」と付きます。既定と違うコマンドは「変更済（既定: Ctrl+S）」と出ます。
  - **割り当て**: 一覧でコマンドを選び、「新しいキー」の欄（読み取り専用）にフォーカスして割り当てたいキーを押すと、`Ctrl+Alt+K` のように表記が入ります（Ctrl／Alt／Shift／Win＋キー、F キーなど。Tab・Shift+Tab は次・前の部品へ移ります）。「割り当て」で確定します。一覧の行のダブルクリックでこの欄へ移ります。表記は `src/command/keys.rs` の形式（大文字小文字・修飾キーの順は正規化）です。
  - 文字入力を奪うキー（修飾キーなしの英数字・記号、Enter・Tab・Space・Backspace。Shift だけを足したものも含む）は割り当てられず、理由を知らせます（Ctrl か Alt などと組み合わせる）。F キー、Delete、矢印、Escape などは単独でも割り当てられます。グローバルショートカットは修飾キーが要ります。
  - **重複**: 別のコマンドが同じキーを使っているときは、「{キー} は「{相手}」が使っています。「{選んだコマンド}」に付け替えますか？（「{相手}」は割り当てなしになります）」と確認します。付け替えると相手は割り当てなし（空文字）になり、やめると何も変わりません。
  - **割り当てを外す**: 選んだコマンドを割り当てなしにする。**既定に戻す**: 選んだコマンドの `keys` の項目を消す（戻した先の既定のキーを別のコマンドが使っているときは知らせます）。**すべて既定に戻す**: 確認のあと、全コマンドの項目を消します（知らないコマンド名の項目は残します）。
  - 画面の中の編集は、OK・適用まで保存しません。OK・適用は他の項目と同じ経路（最新の設定を読み直し、変えたコマンドの `keys` の項目だけを差し替えて保存し、再読み込みと同じ経路でアクセラレーターとメニューのキー表示、グローバルショートカットの登録を替える）で、ほかのウィンドウが変えた別のコマンドの割り当てを失いません。グローバルショートカットの登録に失敗（他のアプリが使用中）したとき、キーの重複などの問題があるときは、状態欄のほか、適用のあとに通知のダイアログを出します。

## 16. 将来の MCP 連携（初版は未実装）

初版では **AI クライアントとの通信は実装していません**。`mcp.enabled` の設定値と、次の設計上の備えだけがあります。

- 全操作を「コマンド」に統一し、メニュー・ショートカット・将来の AI 操作が同じ入口を通ります。コマンドの実行者（利用者／AI）を区別できます。文書やメモを変える操作は前提の版を必須にする設計です。
- コマンド定義（名前・引数・実行可能条件）は機械可読です。
- 中核処理（文字コード、保存、メモ、復元、検索、巨大ファイル索引）は画面から独立しており、`windows` crate に依存しません。
- メモと復元データは、ロック・原子的置換・版の照合により、別プロセスからの同時アクセスでも壊れません。
- 長時間処理は中止・進捗・件数上限の共通の仕組みで扱います。
- 将来の構成（予定）: 同じ EXE を `--mcp-stdio` で起動して JSON-RPC 2.0 で応答し、GUI 起動中は名前付きパイプで GUI へ中継します。現在、`--mcp-stdio` オプションは**ありません**（実行すると通常のファイル名として扱われます。コードの確認による）。

### 要件との差分

| 項目 | 要件 | 実装 |
|---|---|---|
| 巨大モードの切り替え | 実測で決める | 暫定値（256 MiB／1000 万行／8 MiB の行）。実測は未実施 |

| メモ呼び出しキー | 実装時に決める | Ctrl+Shift+M |
| 復元の書き出し間隔 | 実装時に決める | 2 秒の静止／最大 30 秒。設定では変更不可 |
| メモの自動保存 | 入力が落ち着いた時点と正常終了時 | 1.5 秒の静止／最大 10 秒、閉じる・終了時。設定では変更不可 |
| キー設定の変更 | 設定で変更 | 設定画面の「キー」ページ（V4-2。一覧・絞り込み・割り当て・付け替え・外す・既定に戻す）または `settings.json` の編集と「設定を再読み込み」（ウィンドウを前面に戻したときも）で、**再起動なしに反映**（15.1）。キーの入力は 1 つのキーの組み合わせ（コード進行のような連続キーは不可） |

### 既知の制限

- 外部変更の検知は、長さ・更新時刻・ファイル ID によります。同じファイルをその場で同じ長さに書き換え、更新時刻の刻み内に収まった場合は検知できません。ファイル ID を返さないファイルシステム（一部のネットワーク共有など）では長さと更新時刻だけで比べます。
- 保存は「新しいファイルで置き換える」方式のため、**ハードリンクは切れます**。`ReplaceFileW` が使えないファイルシステムでは、属性・ACL・代替データストリームが引き継がれません。
- CP932 には、読み込み → 書き出しで文字は同じでもバイト列が変わる重複登録文字があります。
- 巨大ファイルの検索は行単位です。後ろ向き検索は、窓の境界で 64 KiB を超える一致を見落とすことがあります。
- 通常編集の本文が極端に大きい場合は、巨大モードに切り替わるため、大きなファイルの編集は 256 MiB 以下が目安です。
- メモの削除操作は用意されていません（メモの削除は未確認）。折り返し・書体・タブ幅などの表示の設定は表示メニューにあります（13.1）。巨大ファイルのビューには、行番号の表示以外の表示の設定（折り返し・書体・拡大・空白の表示など）は適用されません。桁指定の折り返しの「桁」は半角 `0` の幅が基準で、比例フォントや全角文字では文字数と一致しません。括弧の強調は 2 MB 以下の文書だけです。
- 拡大・縮小、折り返し、空白・改行記号の表示、強調の見た目は Windows 実機での確認が必要です（`docs/verification/U.md`）。
- 印刷は UI スレッドで同期的に行うため、非常に長い文書では印刷データを作る間、画面が応答しません。巨大ファイルは印刷できません。印刷の見た目（用紙、余白、ヘッダー・フッター、色、行番号、折り返し）は Windows 実機での確認が必要です（`docs/verification/U.md`）。
- 検索・置換・Grep の小窓のキー操作（Esc など）以外の細かな挙動、IME の動作、DPI の見た目、WebView2 プレビュー、Direct2D 描画、グローバルショートカットの前面化、性能計測は、Windows 実機での確認が必要です（`docs/verification/`）。レビュー工程（R1〜R4、最終レビュー）は未実施です。
- Wine 上では Direct2D を使えず、巨大ファイルのビューは GDI で描画します。
